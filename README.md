# 工程方法与小技巧笔记

这是一份长期维护的公司代码审查笔记，记录**数据、训练、部署、推理**各环节相对最基础实现所做的改进。

收录标准：

- 对吞吐、显存、稳定性、可复现性、泛化、控制连续性或安全性有实际作用。
- 能在当前代码中找到明确实现位置。
- 区分“设计存在”“当前配置启用”“已经验证”三种状态。
- 不把普通代码清理、单次调试脚本或泛泛的工程规范混为算法 trick。

阅读方式：

| 分册 | 内容 |
|---|---|
| [数据方法](01-data.md) | 数据读取、缓存、采样、分片、预处理、目标构造 |
| [训练方法](02-training.md) | 目标函数、模型结构、分布式、显存、优化、checkpoint |
| [部署方法](03-deployment.md) | 服务分层、协议、预热、契约校验、启动与故障隔离 |
| [推理方法](04-inference.md) | 编译、TTRTC、动作块调度、平滑、实时控制与安全 |
| [证据与待审清单](05-coverage-and-backlog.md) | 当前代码基线、覆盖范围、未审模块、验证记录 |

状态标记：

- `启用`：当前主配置确认启用。
- `已实现`：代码存在且可配置，但当前任务未必启用。
- `实验`：实验脚本或测试分支，不作为默认路径。
- `已验证`：有运行日志、测试或真机结果支持，会在条目中单列验证证据。

每条记录统一包含：

```text
基础做法 → 改进 → 为什么可能有效 → 代价/风险 → 适用场景 → 代码 → 状态
```

维护规则：

1. 新条目使用稳定编号，例如 `D-012`、`T-021`、`P-008`、`I-015`。
2. 新增代码位置时，优先链接到具体函数或类。
3. 状态变化时追加日期和证据，不删除历史结论。
4. 若方法仅存在于实验脚本或未被主配置引用，必须明确说明。
5. 线上事故驱动的改动同时记录失败模式，避免只记录“修好了”。
