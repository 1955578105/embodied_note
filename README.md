## 先看懂这些词

- **行为克隆**：让模型模仿示范动作。它擅长学习“正常时怎么做”，但不会自动学会偏离后的恢复。
- **Action Chunk（动作块）**：一次预测连续的多步动作，再按顺序执行。动作块越长，推理次数越少，但对突发变化反应越慢。
- **Diffusion Policy / Flow Matching**：两类生成连续动作的方法。它们可以表示多种合理轨迹，但要同时考虑采样时间、随机性和闭环稳定性。
- **TTC / 实时分块**：下一段动作还在推理时，机器人先执行当前动作；新动作会带上已经执行的前缀，减少动作块切换时的回跳。
- **norm / 归一化统计**：把训练中的状态和动作缩放到模型熟悉的范围。权重、归一化统计和动作接口必须成套使用。
- **prefix / 前缀**：新一轮推理中已经执行或必须保持的动作部分。前缀太短会接不上，太长会留下太少的新动作。
- **IK**：逆运动学，把末端目标转换成关节动作；“末端位置合理”不等于关节路径可达或无碰撞。
- **WBC**：全身控制，同时处理浮动身体、接触、平衡和手臂任务，平衡与接触安全通常优先于末端精度。
- **p95 / p99**：延迟分布的尾部指标。机器人偶发一次长延迟就可能耗尽动作队列，所以平均值不够。
- **MCP**：让 Agent 发现并调用工具的一种协议。一个 MCP server 可以提供多个工具，但工具返回成功不等于机器人已经完成物理任务。
- **episode**：一条完整任务轨迹，从开始、执行到结束或失败。把它切得太碎会丢掉阶段之间的因果关系。
- **开环执行**：先预测一段动作，再暂时不看新观测地执行。它能减少推理开销，但环境变化后反应会变慢。
- **DAgger**：让模型先自己执行，记录它偏离专家的状态，再让专家在这些状态上纠正；重点是补足模型实际会遇到的错误状态。
- **本体（embodiment）**：机器人本身及其动作接口，例如不同自由度、关节顺序和夹爪定义。不同本体不能只靠补零拼成同一种机器人。
- **QoS**：ROS 2 的消息传输策略，包括是否可靠、队列多深、消息能保留多久；配置必须符合消息的时效要求。
- **checkpoint**：训练过程快照。可继续训练的快照还应包含优化器、学习率、随机状态和采样进度，不只是模型权重。
- **dropout**：训练时随机屏蔽一部分输入或网络连接，用来减少过拟合；它不等于推理时随机丢帧。
- **Kalman filter（卡尔曼滤波）**：用运动预测和传感器观测反复修正状态的估计方法；时间戳和噪声模型错了，融合反而会抖。
- **FSDP**：把大模型参数、梯度和优化器状态分片到多张 GPU 的训练方式，省显存但增加通信和恢复复杂度。
- **VLA**：视觉、语言、动作模型；它不只回答文字，还要把视觉和指令转成机器人动作。
- **ROS 2**：机器人进程之间交换传感器、状态和控制消息的通信框架。
- **SLAM**：同时估计机器人位置并建立地图；定位漂移时，地图和轨迹会一起出问题。
- **VLN / ObjectNav**：根据语言导航，或寻找指定物体并到达它附近。
- **PID / MPC**：两类控制方法。PID 根据当前误差调节输出；MPC 会用模型预测未来并在约束下选动作。
- **EMA**：参数的指数滑动平均，常用来得到比瞬时训练权重更稳定的评估权重。
- **tokenizer**：把连续动作或文本转换成模型处理的离散表示；压缩得越狠，速度和精度的取舍越明显。
- **prompt**：传给模型的任务描述或上下文；部署时的写法必须和训练时的语义一致。
- **horizon**：一次动作块包含的预测步数；它决定反应速度和动作连续性的取舍。
- **metadata**：描述服务身份和输入输出契约的元数据，例如任务、相机、动作维度和模型版本。
- **TTRTC**：把实时分块、已执行前缀和延迟管理放进训练与推理协议的一套机制。
- **rollout**：让策略在仿真或真机中完整执行一回，用于观察闭环结果，而不是只看单步误差。

## 每题怎么读

每个现象题都按同一条线索组织：先定义症状，再拆出可能根因，然后给出能排除根因的检查，最后说明处理方法、代价和恢复条件。面试时不要一上来报参数；先说你要证明哪一层出了问题。

- **现象**：到底是不动、变慢、抖动、漂移、回跳，还是假完成。
- **时间线**：观测何时采集，请求何时发出，结果何时返回，动作何时发布和被执行。
- **契约**：相机、状态、动作顺序、单位、归一化、任务代次是否一致。
- **资源**：CPU、GPU、网络、队列、锁和控制发布者是否竞争。
- **安全**：应继续、降级、暂停还是清空状态后重新开始。
- **验证**：用固定输入、回放、消融、分层指标和受控真机测试证明修复有效。

### D-001 任务验收判成功，策略却无法稳定复现

**面试问法**：都说任务数据是成功的，为什么训练出的动作没有一致结果？

**现象**：采集记录标成成功，但终端姿态、物体位置、动作路径和人工干预差异很大，模型同时学到多套无法兼容的策略。

**常见误判**：先怪模型容量不够或数据量太少，却没确认“成功”到底指最终物体进入目标，还是中间动作也满足明确条件。

**根因链**：

- 成功条件只写在采集人员脑子里。
- 同一个 最终状态可能由不同动作路径达到。
- 失败后发现人工拖动或手工修正，但数据仍标为全自主成功。
- 任务目标没有拆分阶段，模型无法知道当前应该执行哪一段。
- 动作接口与验收指标不一致，例如视觉上到位但夹爪仍输出关闭。

**排查顺序**：

1. 抽样查看成功样本的完整轨迹，而不是只看最后一帧。
2. 检查是否有人工干预、物体移动或 reset 操作未被记录。
3. 统计终端状态、阶段时长和动作路径的多峰程度。
4. 对同一任务写出可执行验收规则，并重新标记无法确定的数据。
5. 比较只使用“严格成功”数据与混杂成功数据的闭环表现。

**处理方法**：把任务目标、动作接口、阶段里程碑 和物理验收一起定义；记录失败、恢复和人工介入；必要时把长任务拆成有明确前置与后置条件的技能。

**面试回答**：机器人数据的成功不是最后一帧好看，而是从给定初始条件出发，使用可执行动作接口完成可验证的物理状态。任务、动作和验收定义不一致，会让模型学习到多套甚至互相冲突的策略。

**追问**：

- 只给终端 RGB 成功标签，为什么可能学不好接触动作？
- 怎样区分成功路径不同与数据噪声？
- 为什么“人工拖动到终点”不能当成全自主成功数据？

### D-002 同一任务换操作者后成功率骤降

**面试问法**：训练集很大，为什么换一个操作者或采集设备就明显变差？

**现象**：模型在训练机器人、固定工位和主要操作者上稳定，换人后接近速度、抓取高度、动作节律和恢复习惯都不同。

**根因链**：示教数据实际上采样了某个操作者群体的策略，而不是任务本身的广泛可行分布。操作者会偏向惯用手、固定抓取点和特定动作风格，设备也会带来主从比例和反馈延迟差异。

**排查顺序**：

1. 按操作者、机器人、设备和场景分别计算成功率。
2. 固定物体与环境，只更换操作者，检查动作方差。
3. 比较起始姿态、抓取点、速度峰值和恢复动作覆盖。
4. 检查是否所有成功样本都来自同一位熟练操作者。

**处理方法**：增加多操作者、多初始位姿和多设备采集；对操作者身份不需要输入模型时，用数据多样性让模型学习任务不变量；保留少量专家轨迹作为稳定示范，同时补采普通操作者的恢复行为。

**常见误判**：只通过左右镜像或视觉增强模拟多人示教。增强可以改图像，却不能创造新的接触策略和错误恢复。

**面试回答**：示教数据代表的是操作者与设备的联合策略分布。需要按操作者和设备做分层评测，并用真实多样示教覆盖任务不变量，而不是只增加同一风格的重复轨迹。

**追问**：

- 操作者越多一定越好吗？
- 怎样判断模型学的是任务，而不是某个人的动作习惯？

### D-003 主从遥操作看起来顺，回放时动作不可用

**面试问法**：采集时操作员觉得非常顺手，为什么训练或回放出来的机器人姿态不自然？

**现象**：遥操作现场闭环正常，但保存下来的动作映射回机器人后出现方向偏、速度过快、姿态不可达或末端轨迹和视频不同步。

**根因链**：

- 主设备和从设备尺寸不同，直接直观映射并不等于同一关节语义。
- 视场和相机位置导致操作员补偿感知延迟，保存的是补偿后的动作。
- 主从零点、方向、缩放和工作空间不一致。
- 采集线程记录的是发送前、发送后还是执行后的值没有明确。
- 操作员用动作修正自己看到的旧反馈，离线回放失去闭环。

**排查顺序**：

1. 用已知方向的小幅动作逐轴检查正负号和缩放。
2. 对比主设备输入、机器人命令、机器人实际状态和图像时间。
3. 用单一动作回放，确认离线动作与在线姿态一致。
4. 检查工作空间边缘、奇异点和关节限位附近是否发生饱和。
5. 检查相机视角和显示延迟是否诱发过度修正。

**处理方法**：固定主从映射协议，标定零点和工作空间，记录指令与实际状态；对超出可达范围的动作显式截断或告警；让采集显示延迟接近部署条件。

**面试回答**：遥操作数据的“人在环里手感好”不等于离线动作正确。要保存机器人实际可执行动作，并保证主从标定、延迟、单位和坐标系在采集与回放一致。

**追问**：

- 为什么录制主设备位置有时不如录制从设备命令？
- 遥操作现场闭环会不会掩盖动作错误？

### D-004 长任务拆成片段后每段会做，连起来不会

**面试问法**：每个子技能单训成功率都高，为什么串成完整任务就失败？

**现象**：模型能拿杯子、能运输、也能放下，但不知道何时开始下一阶段，前后技能接口不一致，失败后也不会返回合适阶段。

**根因链**：

- 一条完整任务轨迹（episode）切得过碎，丢失阶段转移上下文。
- 每段动作坐标系或终止条件不同。
- 没有记录开始、成功、失败和人工取消的明确边界。
- 训练只覆盖每个阶段内部，不覆盖前后阶段和恢复。
- 高层的任务描述与低层技能名不一致。

**排查顺序**：

1. 画出阶段状态、前置条件、退出条件和交接观测。
2. 检查每个子数据集的动作类型、单位和相机是否一致。
3. 单独回放各阶段，再回放各阶段组合边界。
4. 统计失败发生在阶段识别、动作切换、物理执行还是进度判断。
5. 检查阶段标签是否由视频推测，而没有采集事件证据。

**处理方法**：定义层次化 episode 与阶段事件；保留阶段之间的上下文；同时采集失败、重试和恢复；高层用技能或阶段接口，低层负责动作执行。

**面试回答**：原子技能成功不保证组合成功。长任务需要明确的阶段语义、交接状态、失败恢复和统一动作契约；episode 切分应与这些因果边界一致。

**追问**：

- 长 episode 和短 episode 各自的风险是什么？
- 为什么仅把多段动作拼成一条轨迹不等于长任务数据？

### D-005 验证集接近满分，换房间或换日期就失败

**面试问法**：训练和验证 loss 都很好，为什么实际部署很差？

**现象**：验证集指标很高，但换房间、光照、物体实例或采集日期后成功率骤降。

**根因链**：数据划分泄漏。同一 episode 的相邻帧被随机分到训练和验证，同一房间布局、同一操作者和同一天采集的数据同时出现在两边。

**排查顺序**：

1. 检查是否按帧随机切分，而不是按 episode、场景、日期或操作者切分。
2. 检查 norm、特征选择或超参数搜索是否偷看测试集。
3. 在验证中逐步加入未见过房间、物体实例、来宾操作者和光照变化。
4. 比较同分布验证集与独立测试集的分差。
5. 把人、物体和场景身份做成审计字段，检查偶然泄漏。

**处理方法**：按因果单元、场景或部署时间切分；保留独立测试域；报告每组场景的结果；训练中需要泛化时增加真实变化，而不是把测试域换个随机 seed。

**面试回答**：高验证分只说明在特定划分上没有见过完全相同的帧。机器人验证要问“看到了多少新轨迹、新场景和新条件”，而不是只看随机帧有没有重复。

**追问**：

- 同一场景不同相机算不算泛化？
- 如果不按帧随机切分，数据量少时怎么办？

### D-006 加入触觉或深度后，模型反而退化

**面试问法**：多模态通常应该更强，为什么加力传感器或深度反而变差？

**现象**：多模态模型训练 loss 更低，但在接触、透明物体或未见过传感器状态下成功率下降。

**根因链**：

- 触觉、力、深度和图像频率不同，简单拼接发生时间错位。
- 单位、坐标、标定和缺失规则不一致。
- 少量传感器数据被大数据集视觉样本淹没。
- 某些模态在训练分布外的噪声很大，模型却被迫依赖。
- 多模态输入增加了参数量和过拟合风险。

**排查顺序**：

1. 只加一个模态做消融。
2. 检查该模态单独作为唯一输入能否完成任务。
3. 对比各模态的延迟、缺失率和量纲。
4. 检查训练与真机预处理是否一致。
5. 分析模型是否只在特定接触阶段使用该模态。

**处理方法**：为每个模态独立归一化和时间戳；屏蔽不可信输入；先建立视觉基线再增量加入；随机屏蔽部分输入模态（modality dropout）或使用门控；按接触阶段评估收益。

**面试回答**：新增模态只有在提供了可学习的新信息、且同步与标定可靠时才有价值。它不是自动增益，还可能让模型学到只在采集设备上成立的伪相关。

**追问**：

- 触觉全为零表示没有接触，还是传感器故障？
- 力传感器与相机应该按帧数还是按时间对齐？

---

### D-007 数据规模扩大，GPU 反而更常等待数据

**面试问法**：数据集变大后训练没更快，GPU 利用率还下降了，为什么？

**现象**：启动和首个 step 都很慢，GPU 长时间等待；多个 worker 打开大量小目录，或随机读视频时频繁重开。

**根因链**：索引构建、文件句柄、随机 I/O、视频解码、传输和 collate 都可能成为瓶颈。部分小数据根之间频繁切换，打开成本高于实际读取。

**排查顺序**：

1. 分别测数据索引、随机访问、图像或视频解码、worker 排队和 GPU 前向。
2. 检查每个 worker 的句柄数和内存。
3. 检查小目录数量和随机访问比例。
4. 比较单 worker、多 worker、缓存开启和分片读取。
5. 检查首个 epoch 与稳定阶段差异。

**处理方法**：惰性打开；worker 级有限缓存；把大量小数据根整理成只读分片；顺序预取和缓存预热；预热索引；保证缓存淘汰不会造成频繁抖动。

**面试回答**：大数据训练要先定位 I/O 瓶颈。数据量增大不一定增加显存，却会放大索引、打开、解码和随机调度成本；优化应针对真实瓶颈，而非只扩 worker。

**追问**：

- worker 越多为什么可能更慢？
- 分片后如何保证样本语义和随机性没有改变？

---

### D-008 数据飞轮越采越多，失败模式却越来越集中

**面试问法**：模型自主采集后持续加数据，为什么提升很快停滞？

**现象**：采集量不断增加，但重复展示同类错误，或模型只在自己的失败分布上过拟合；部分未触发状态永远不被采到。

**根因链**：

- 自主策略决定采集，没探索未触发状态。
- 只选低置信或人工纠错样本，忽略成功但不稳妥状态。
- 采集日志不知道失败类型，补采比例失衡。
- 新增数据分布和真实产品分布不一致。
- 评测也用模型自身输出筛选，形成闭环偏差。

**排查顺序**：

1. 按失败类型、场景和触发条件统计有效样本。
2. 比较自主采集分布与部署分布。
3. 检查未触发状态的覆盖，而不是只看总帧数。
4. 使用独立测试场景检验飞轮是否真改善。
5. 给新数据加来源和版本，避免旧错误被重复加权。

**处理方法**：结合自主执行、人工纠错、失败重放和主动探索；以任务价值和覆盖差分配权重；定期重新采样，不把采集量直接等同于价值。

**面试回答**：数据飞轮的价值来自定向修正，不是普通累积。要维护失败分类、覆盖缺口和独立评测，防止模型只学习自己的偏差。

**追问**：

- 只采失败样本会导致什么？
- 成功但低置信的样本为什么也有价值？

---

### D-009 人工接管数据都在，训练集却分不清谁在控制

**面试问法**：已经录制了人工接管，怎样判断这些数据真的能教模型恢复？

**现象**：接管视频和关节数据都存在，但数据集无法明确区分模型自主、人工接管、人工释放和恢复后的自主片段。训练后模型可能一直等待人工，也可能把人工动作误当成自主策略。

**根因链**：

- 模型动作和人工动作混合在一条时间线，却没有标明控制权切换。
- 接管后的观测无法追溯到触发前状态。
- 人工动作使用不同设备或不同坐标系。
- 接管只记录动作，没有记录人工释放和恢复条件。
- 数据中大量正常片段稀释少量介入片段。

**排查顺序**：

1. 重建控制权时间线：模型执行、人工触发、人工动作、释放、模型恢复。
2. 确认触发前状态、模型动作和人工动作对齐。
3. 检查介入片段是否标为独立控制源，并记录触发原因。
4. 对接管前后窗口做可视化回放，确认边界没有错一帧或跨 episode。
5. 用相同初始状态比较带标记和不带标记的数据。

**处理方法**：保存干预 id、控制源、切换时间、触发原因、释放事件和恢复条件；把自主动作、人工动作和恢复后的自主动作明确分段；让训练采样能单独统计介入数据。

**面试回答**：介入数据首先是一个控制权标注问题。只有把触发前状态、人工动作、释放事件和恢复条件分开，训练算法才有机会学习恢复；具体怎样利用这些片段训练策略，属于训练分布问题。

**追问**：

- 哪些介入片段应该进入主策略，哪些只用于评测或重采样？
- 为什么控制权边界需要单独记录，而不能从动作值反推？

---

### D-010 日志不报错，某个数据源却几乎从未被采样

**面试问法**：训练混合了几十个数据源，loss 正常，为什么某个任务完全没学会？

**现象**：数据路径存在、数据集大小也在报告，但小任务被大任务压制，或在分组采样后某些 batch 完全没有它。

**根因链**：

- 按自然样本数采样，大源几乎独占梯度。
- 多重采样权重叠加，预期的有效权重被抵消。
- 固定 batch 边界或分桶让某来源长期落在同一位置。
- worker 和 sampler 的 epoch 状态不同步。
- 数据源内部再进行截断或过滤，实际有效样本远少于报告数量。

**排查顺序**：

1. 统计每个任务、机器人、场景在 batch 中的真实出现比例。
2. 检查 sampler 配置和外层数据集权重是否重复相乘。
3. 检查 batch 内是否有边界均衡和去重策略。
4. 验证每个 worker 的切分和恢复是否正确。
5. 对稀少任务单独评测，而不是只看总 loss。

**处理方法**：显式设置任务和来源权重；保持子数据集边界统计；记录 batch 级来源分布；让权重变化同时伴随验证集与 norm 检查。

**面试回答**：数据混合的指标应是有效采样分布，不是目录大小。需要按 batch 和任务记录出现比例，防止大数据源与权重叠加后让小任务事实消失。

**追问**：

- 按 dataset 大小开根号采样解决什么问题？
- 某任务被过采样后为什么可能过拟合？

---

### D-011 标定或固件升级后，旧数据回放对不上机器人

**面试问法**：数据文件没变，为什么升级相机标定或机器人固件后，旧数据回放与机器人对不上？

**现象**：同一相机或机器人换设备后画面不同，动作回放速度不同，实验也出现难以解释的变化。

**根因链**：

- 相机内外参、安装角度或曝光不同，但文件名仍相同。
- 控制频率、时间戳或标定参数变化。
- 数据文件被原地覆盖，没有版本记录。
- 采样脚本、norm 或过滤规则与数据目录不一致。
- 机器人固件或夹爪零点变化但未记录。

**排查顺序**：

1. 核对相机标定、设备序列号、固件和动作接口版本。
2. 比较原始时间戳与回放频率。
3. 记录数据集配置、norm 和筛选结果哈希。
4. 用固定 episode 回放并比较第一帧与末帧。
5. 检查资产目录是否被原地替换。

**处理方法**：将数据、标定、处理配置和设备元数据作为一个版本发布；原地修改前生成可恢复备份；回放固定 episode 做回归。

**面试回答**：数据可复现不只看文件路径。设备标定、时钟、动作解释和处理脚本都是数据语义的一部分，任何变化都应进入版本。

**追问**：

- 为什么只记录文件修改时间不够？
- 怎样把 robot firmware 纳入数据版本？

---

### 数据现象题通用答题框架

1. 确认任务、成功条件和动作接口是否一致。
2. 确认数据采集过程、控制权和设备标定。
3. 确认训练、验证、测试是否按因果单元拆分。
4. 确认采样分布和多模态时间对齐。
5. 确认数据版本、norm 和权重是否同代。
6. 用错误类型、来源和场景分层报告结果。

### 一页总结

数据题的高分答案不是“多采一点”，而是找到数据分布为何没有覆盖目标、训练为何没有看到该分布、验证为何高估能力，以及资产版本为何无法复现。跨模块的相机缺失、同步错误、动作布局和缓存污染见[跨模块故障题](#cross-module)。

### T-001 开头能做对，越往后越偏

**面试问法**：行为克隆的 loss 很小，为什么机械臂执行一会就偏出轨迹？

**现象**：模型在离线样本和固定起点表现稳定，真机闭环后逐渐漂移，一次小误差无法自行纠正。

**根因链**：示范数据只覆盖专家轨迹附近状态；部署偏离后进入未训练观测；模型输出进一步放大误差。这就是复合误差和协变量偏移。

**排查顺序**：

1. 用同一初始状态执行，看误差从哪一步开始扩大。
2. 比较模型访问状态与示范状态的分布距离。
3. 检查是否执行完整动作块而极少重规划。
4. 检查相机、状态和动作的时序是否一致。
5. 让专家在模型失败状态上补动作，验证恢复能力。

**处理方法**：采集恢复和失败状态；缩短开环执行；动作块内部平滑；DAgger 或人工纠错；加入状态、历史和闭环重规划。

**面试回答**：行为克隆优化的是示范分布上的动作预测，不是实际闭环成功。小误差会把策略带入新状态，必须用错误状态覆盖、及时重规划或纠错数据来缓解。

**追问**：

- 为什么缩短动作块能缓解但不一定根治？
- loss 很小为什么仍可能有动作多峰问题？

---

### T-002 模型能模仿专家，却不会从自己的错误恢复

**面试问法**：只增加专家成功示教，为什么还是经常卡在偏离后的状态？

**现象**：模型从起点执行良好，但一被扰动、碰撞或物体偏移就不知道怎么做。

**根因链**：专家示范很少访问模型自己的错误状态；成功数据缺少恢复、失败和接管动作；强化学习若只在仿真中优化，仍未覆盖真机延迟和视觉。

**排查顺序**：

1. 记录模型自主执行中实际出现的错误状态。
2. 比较成功示范、接管纠错和失败片段的有效比例。
3. 确认人工动作属于哪个控制源、何时触发和释放。
4. 在同一初始状态比较加入纠错前后的恢复表现。
5. 检查强化学习奖励是否与真实任务验收一致。

**处理方法**：让模型自己执行，记录它偏离专家的状态，再让专家在这些状态上纠正（DAgger）；同时加入人工接管、失败重采样或仿真强化学习。关键不是算法名称，而是训练数据要覆盖部署时真的会出现的偏离。

**面试回答**：行为克隆教模型在专家走过的状态上怎么做；DAgger 和人工纠错补充模型自己走偏后的状态；强化学习再根据长期结果优化。选择哪一种，要看真实错误数据和安全成本。

**追问**：

- 只采失败视频能用于训练吗？
- 为什么人工纠错的触发时刻本身就是监督信息？

---

### T-003 同一画面换成另一个抓取指令，动作却完全不变

**面试问法**：同一画面把“抓杯子”换成“抓碗”，为什么 VLA 的输出几乎不变或抓错同类实例？

**现象**：视觉分类看似正确，但语言指令变化没有改变目标实例、空间关系和动作；模型可能只依赖画面中最显眼物体。

**根因链**：训练样本的语言条件与视觉场景高度共现，模型靠背景或物体先验走捷径；同一类多个实例、关系描述和同图换指令覆盖不足。

**排查顺序**：

1. 固定画面，只改变目标类别、实例和空间关系，观测动作是否变化。
2. 在同一画面加入多个同类物体，检查目标选择。
3. 检查训练数据是否语言和物体长期强共现。
4. 比较纯视觉基线、文本条件和视觉语言联合条件。
5. 检查目标实例检测与动作坐标是否对齐。

**处理方法**：增加反事实指令和同类多实例数据；引入显式目标检测、关键点或空间关系；分别评测语言遵循与动作执行；在高风险任务保留独立实例验证。

**面试回答**：类别识别正确不等于理解指令。要用同图换指令和多实例测试语言是否真正控制动作；若输出不变，优先检查训练共现偏差和目标定位，而不是继续加动作损失。

**追问**：

- 只做视觉识别测试能否证明模型理解了语言？
- 如何区分模型抓错实例和 IK 不可达？

---

### T-004 画面里有多条合理路径，模型却总走中间撞上障碍

**面试问法**：同一画面有左侧和右侧两条绕行路线，为什么回归模型总选中间？

**现象**：数据中有多峰动作，模型输出平均动作，结果既不左也不右。

**根因链**：同一画面可能同时存在左绕和右绕两种正确动作。普通均方误差会把两种答案平均到中间，得到一个实际上两边都不安全的动作。

**排查顺序**：

1. 聚类同一状态附近的目标动作，确认确实多峰。
2. 比较单峰回归、离散 token 和生成式动作头的表现。
3. 检查采样随机性是否被完全关闭。
4. 检查是否有任务条件或历史可用于消歧。

**处理方法**：使用离散动作 token、Diffusion、Flow 或混合密度模型；加入任务条件；保留合理的动作多样性并用真机评测验收。

**面试回答**：回归输出条件均值，多峰时可能变成危险折中。生成式或离散动作头适合多模式轨迹，但还需要控制采样、延迟和部署一致性。

**追问**：

- 多峰动作下简单的 MSE 为什么看起来更平滑？
- 生成动作头的随机性会不会让真机重复性变差？

---

### T-005 动作块更长，为什么反而更容易在突发时失效

**面试问法**：Action Chunk 提高了轨迹连贯性，为什么障碍出现后机器人反应变慢？

**现象**：模型一次预测多步动作，执行过程中环境变化或物体被碰走，机器人仍继续旧开环轨迹。

**根因链**：动作块执行期间暂时不看新观测。块太长时，环境已经变了，模型还在执行旧计划；重规划频率没有随着任务风险调整。

**排查顺序**：

1. 记录预测块长度、执行比例与重规划时间。
2. 比较只执行块前缀和整块执行的响应。
3. 检查是否使用实际执行进度重对齐。
4. 评估突发场景中的动作停止与人工接管。

**处理方法**：只执行前缀；提前预取；按风险或轨迹分歧缩短 horizon；在危险状态优先停止或重观测。

**面试回答**：动作块降低短视误差和推理频率，但增加开环时间。执行长度是稳定性、延迟和反应性的联合取舍。

**追问**：

- 块太短为什么又会产生新抖动？
- 为什么不能只按固定秒数切动作块？

---

### T-006 只知道画面里的胳膊，却不知道机器人内部姿态

**面试问法**：仅凭图像能否控制机器人？

**现象**：相机被遮挡或机械臂在画面外时，模型动作明显不稳；夹爪开合、关节角或底盘状态无法从画面精确判断。

**根因链**：状态信息缺失或投影方式不合适。多数操作需要机器人本体姿态、夹爪行程和历史动作上下文。

**排查顺序**：比较纯图像、图像加状态、状态缺失和数据布局变化；检查状态归一化、关节顺序和时间戳；检查模型是否把无效 padding 当真实状态。

**处理方法**：用独立状态 token、前缀或条件向量注入机器人状态；布局显式声明；缺失时用 mask；训练和部署共享状态契约。

**面试回答**：图像提供环境语义，状态提供本体精确条件。二者互补，不能用一个通道替代另一个；关键是布局、归一化、时间与有效性。

**追问**：

- 为什么把关节角转成文本不一定比连续状态表示好？
- 状态缺失时应补零还是显式掩码？

---

### T-007 多本体联合训练后，小机器人任务被大本体淹没

**面试问法**：多个机器人共用模型时，为什么大本体还能工作，小自由度任务却被训练没了？

**现象**：接口已经校验正确，但小本体在联合训练后成功率下降；共享参数被大本体样本主导，输出头容量无法区分本体。

**根因链**：各本体数据量、动作维度和任务难度不均；共享动作投影与采样权重让小本体梯度被淹没；只补零而没有本体专属映射。

**排查顺序**：

1. 按本体分别统计样本和真实梯度比例。
2. 检查 embodiment 标识、动作布局和维度 mask。
3. 比较共享投影与本体专属投影。
4. 做单本体微调和联合训练对照。
5. 分别评测每个自由度与任务。

**处理方法**：本体分层采样；维度 mask；本体专属输入输出投影；动作归一化；保留单本体回退与回归评测。

**面试回答**：联合训练时不仅要能区分本体，还要确保每个本体的梯度不被大来源淹没。共享语义骨干与专属动作映射、规范和评测应同时设计。

**追问**：

- 本体专属输出头是否一定解决负迁移？
- 如何判断问题是采样比例还是动作投影容量？

---

### T-008 动作 L2 误差很低，接触法向力却仍然超限

**面试问法**：位置动作的 L2 误差已经很低，为什么插孔、擦拭或夹取时仍会卡死或压坏物体？

**现象**：轨迹位置接近示范，进入接触阶段后法向力、速度或迟滞超出允许范围。

**根因链**：L2 指标没有直接表达接触力、速度、刚度和时间滞后；数据缺少力触觉或接触事件，模型把自由空间轨迹拟合当成任务成功。

**排查顺序**：

1. 按自由空间、接近、接触和退出阶段拆分。
2. 对比位置误差、速度、法向力和滑动。
3. 检查训练样本是否包含接触与恢复。
4. 在受控真机回放并测量实际力。
5. 比较加入力触觉或柔顺控制后的结果。

**处理方法**：加入力触觉、速度与阻抗条件；按接触阶段加权；在线闭环接触反馈；独立验收法向力、滑动和成功率。

**面试回答**：位置误差不能代表接触是否安全。接触题需要额外监督力、速度、刚度和阶段，并用独立接触指标验收。

**追问**：

- 为什么接触阶段需要阻抗或力位混合控制？
- 只增加视觉分辨率能否解决法向力超限？

---

### T-009 某动作维度几乎不收敛，其他维度却正常

**面试问法**：总 loss 在下降，为什么某个关节或夹爪学不会？

**现象**：整体误差改善，但少数维度长期偏大，或模型越权输出。

**根因链**：维度量纲差异大、无效维度被误监督、维度权重过低、夹爪分布近离散、mask 与本体布局错位。

**排查顺序**：逐维统计误差、归一化分布和损失权重；检查有效维 mask；比较只在故障维上的 loss；检查数据是否真有该维运动。

**处理方法**：按维度归一化；显式有效 mask；调整 loss 权重；对夹爪单独阈值和分类建模；检查动作方向与单位。

**面试回答**：总 loss 正常可能掩盖少数关键维欠拟合。要按动作语义、有效维和阶段报告误差，避免 padding 和权重抵消真实问题。

**追问**：

- mask 应用位置为什么会影响噪声和梯度？
- 夹爪开合方向错误能否从总 loss 看出？

---

### T-010 加入辅助 token 损失后数值降了，策略却没提升

**面试问法**：FAST 或辅助 token loss 好用，为什么真机动作没有改善？

**现象**：总 loss 和辅助 token loss 都下降，连续动作成功率不变，甚至更差。

**根因链**：辅助目标可能通过 attention 或共享 prefix 泄漏目标；总 loss 被辅助项主导；token 化偏重长期结构而对接触精度无帮助；训练改善不传递到闭环。

**排查顺序**：分别监控连续 flow loss、辅助 token loss、动作误差和真机成功率；检查 mask 是否隔离预测目标；做无辅助目标消融；比较样本级结果。

**处理方法**：隔离各目标注意力；分开损失权重；只把辅助目标当表征学习手段；保留连续动作主路径；用闭环和分层测试判断收益。

**面试回答**：辅助目标的收益必须由主策略闭环验证。token loss 降低只说明离散目标拟合变好，不能代替动作质量和成功率。

**追问**：

- 多目标训练为什么容易从错误位置改善 loss？
- 如何证明辅助目标改善了视觉表示而不是泄漏答案？

---

### T-011 多任务联合训练后，每个任务都变差

**面试问法**：多任务训练不是应该互相帮助吗？为什么会负迁移？

**现象**：总数据更多，但单任务成功率下降；某些任务被大来源支配，动作接口或视觉相机冲突。

**根因链**：数据量不均、任务语义冲突、动作空间不同、共享参数容量不足、学习率对部分任务不合适。

**排查顺序**：按任务、来源、本体分别评估；计算真实采样比例；比较共享和专属投影；做大小任务权重消融；检查 prompt 与动作契约。

**处理方法**：任务权重、分组采样、本体专属投影、阶段课程、预训练后单任务适配；保留旧任务回归集。

**面试回答**：多任务共享能提高泛化，但优化目标是有效任务分布。必须让采样、动作接口和评测按任务独立，不能只看总 loss。

**追问**：

- 为什么按数据量自然采样会让小任务消失？
- 任务专属参数是否一定更好？

---

### T-012 单卡能跑，多卡吞吐不升反降

**面试问法**：多卡训练为什么不天然更快？

**现象**：GPU 数量增加，每步变慢，GPU 利用率时高时低。

**根因链**：模型太小导致通信占比高；数据不足每卡 batch 变小；同步、参数收集和 checkpoint 阻塞；负载不均。

**排查顺序**：比较单卡、单机多卡和多机；记录前向、反向、通信、数据与保存耗时；检查 batch 规模与每 rank 样本数。

**处理方法**：数据并行、FSDP/ZeRO、梯度累积、分布式采样、通信重叠和合理 batch；先测吞吐再扩卡。

**面试回答**：并行扩展的瓶颈是通信和负载。需要按模型大小、显存上限和集群互联选择策略，不能以卡数推断速度。

**追问**：

- 模型装得下时为什么 DDP 常比 FSDP 简单？
- 为什么 checkpoint 会周期性拖慢训练？

---

### T-013 模型训练中途突然变慢或显存尖峰

**面试问法**：配置没变，为什么新样本或新分支让 step 时间突变？

**现象**：前几千步稳定，遇到新图像尺寸、历史帧数量、任务长度或辅助目标分支时变慢甚至 OOM。

**根因链**：动态 shape 重新编译；多帧缓存增加激活；分支首次分配内存；梯度检查点或通信临时增多；保存与编译同时发生。

**排查顺序**：记录输入 shape、分支、激活峰值、step 内各阶段、保存时点；比较开启和关闭 checkpoint 或 compile。

**处理方法**：固定 shape 或分桶；预热分支；提前规划显存；对昂贵层选择检查点；优化保存时机。

**面试回答**：训练峰值会随真实样本形状和分支变化，不能只看静态模型权重。必须监控激活、临时缓冲和编译行为。

**追问**：

- 为什么平均显存正常仍会突然 OOM？
- 梯度检查点是否一定能提高吞吐？

---

### T-014 强化学习奖励上涨，真实任务表现反而变差

**面试问法**：奖励是训练目标，为什么奖励高了任务却不成功？

**现象**：训练 reward 和 episode 长度改善，真机安全、成功率或人类观感变差。

**根因链**：奖励作弊；辅助奖励主导；仿真规则漏洞；奖励与任务验收不一致；策略利用视觉或物理漏洞。

**排查顺序**：用独立验收器检查；按任务失败类型分解；对异常成功轨迹回放；检查奖励各项的贡献。

**处理方法**：把任务成功作为独立验证；限制奖励权重和漏洞；加入随机压力测试；必要时用人类反馈，但不替代物理安全。

**面试回答**：强化学习优化的是奖励函数，而不是你的主观目标。必须让奖励、验收与真实任务对齐，并监控 reward hacking。

**追问**：

- 课程学习如何影响策略分布？
- 为什么仿真中的成功奖励不能直接算真机泛化证据？

---

### T-015 训练过程正常，却无法解释慢在哪一步

**面试问法**：GPU 利用率不高，怎么系统判断是数据、计算、通信还是保存？

**现象**：每秒 step 数下降，但只看到总耗时，无法定位。

**根因链**：缺少分阶段计时和尾部延迟；数据加载、前向、反向、优化器、EMA、checkpoint、通信混在一起。

**排查顺序**：采集数据等待、图像预处理、模型前向、反向、优化器、通信、保存、日志的均值与 p95；一次只改一个变量。

**处理方法**：分段 profiling；记录异步线程和 GPU 事件；监控 GPU 显存与通信；保留可复现输入。

**面试回答**：性能优化先建立可分解时间线。总吞吐下降不是充分证据，必须知道哪一段在等待，以及尾部还是平均。

**追问**：

- 为什么 checkpoint 保存会形成周期性尖峰？
- 多卡训练为何要分开计算与通信时间？

---

### T-016 论文里的 scaling 结论复制不到自己的机器人

**面试问法**：模型和数据都扩大，为什么你的成功率没有按论文规律提升？

**现象**：参数量和数据量变大但收益有限，目标任务的失败来自接触、动作接口或延迟。

**根因链**：论文任务与机器人、数据和评价分布不同；可 scale 的通用语义不能自动解决动作精度、时序和安全；数据质量不足。

**排查顺序**：按数据规模、任务多样性和模型规模分别做受控实验；看分层成功率；区分数据量、覆盖和重复；核查模型与部署成本。

**处理方法**：先增加有价值的数据覆盖，再扩模型；保持相同评测；记录采样、架构和推理延迟。

**面试回答**：scaling 不是单一参数曲线，取决于模型、数据质量、任务分布和可测指标。不能把论文结论直接外推到所有机器人。

**追问**：

- 数据量增加但多样性不增加会怎样？
- 小模型为什么可能在低延迟部署中更优？

---

### 训练现象题答题框架

1. 先判断是数据分布、损失目标、模型容量、训练稳定性还是部署契约。
2. 比较离线预测与闭环执行，区分代理指标和真实任务。
3. 按任务、动作维、阶段、机器人和场景分层。
4. 一次只改变一个变量，保留同一评测集。
5. 证明收益时同时报告失败类型和副作用。

### 一页总结

训练题的核心不是背某个模型，而是解释“监督信号是否覆盖部署分布、优化目标是否对应真实成功、权重能否在新本体和实时执行下保持语义”。跨模块的资产、显存、推理、队列和控制现象见[跨模块故障题](#cross-module)。

### P-001 一个程序能做任务，但换模型、换工具就全部重写

**面试问法**：早期 demo 能跑，为什么业务一多就难维护？

**现象**：语音入口、模型加载、相机读取、动作发布和任务判断混在一个程序；换模型或换动作载体时要改全部调用方。

**根因链**：

- 用户意图、能力名、服务地址和 ROS 发布耦合。
- 模型生命周期与机器人控制生命周期相同。
- 多个任务手工复制启动脚本。
- 工具调用结果没有统一失败语义。

**排查顺序**：

1. 画出从用户指令到关节命令的组件和所有权。
2. 识别哪些能力是公开业务接口，哪些是内部实现。
3. 区分传感器、控制、推理、编排和验收。
4. 检查每层是否能够独立替换与测试。

**处理方法**：Agent 负责意图和工具选择；工具接口负责公开动作与验收；客户端维护 ROS 与动作队列；策略服务只做推理；底层控制器持有限位与安全。

**面试回答**：端到端系统把语义、动作和控制耦合在一起，短期路径简单但难定位和替换；模块化增加接口与时序成本，却能明确所有权、独立验收和安全边界。Agent 不应直接持有 GPU 地址和关节发布权，模型服务也不应越过机器人侧安全层。

**追问**：

- 多一层通信会增加什么故障面？
- 哪一层应该拥有急停与发布权？

---

### P-002 Agent 能调用机器人工具，却不知道哪些能力可用

**面试问法**：MCP server 可以有多个工具，如何让 Agent 知道该调用哪个？

**现象**：工具列表很多，描述相似，Agent 调错导航、VLA、回放或恢复工具；新任务需直接改主程序。

**根因链**：工具输入、描述、前置条件和返回语义缺少统一动作目录；内部 pipeline 和公开 action 混在一起。

**排查顺序**：整理公开能力表，检查参数、前置条件、副作用、超时、取消和验收；把内部端口与模型名从用户可见动作中移除。

**处理方法**：一个 MCP server 暴露多个命名工具；公开 action 目录映射到内部路由；Agent 只看到业务动作，工具返回可验证结果。

**面试回答**：MCP 是工具发现与调用接口，不是模型本身。一个 server 可提供多工具；关键是每个工具的语义、权限、失败和结果可被统一测试。

**追问**：

- 工具名与模型 prompt 为什么要分离？
- 工具描述如何避免 Agent 误选相近动作？

---

### P-003 导航成功、抓取成功，组合任务却卡在流程里

**面试问法**：每个工具都有统一 success，为什么长任务仍未完成？

**现象**：导航完成、抓取也完成，但后续没有触发放置；失败重试无限循环；用户取消后旧任务仍运行。

**根因链**：各工具只返回完成动作，不返回前置、后置和物理验收；流程编排没有状态、超时、取消和恢复。

**排查顺序**：

1. 写出状态、事件和转换条件。
2. 检查每步是否有前置条件与观测证据。
3. 检查取消和重试是否传播到执行端。
4. 检查旧工具响应是否被新会话消费。

**处理方法**：状态机或行为树；显式任务阶段；请求代次；步骤级结果与超时；失败回退与人工接管。

**面试回答**：工具完成不等于世界状态满足下一步条件。长任务需要有状态的编排和物理验收，不能用一个布尔 result 代表所有阶段。

**追问**：

- 为什么行为树比一个巨大 if/else 更容易扩展恢复？
- 用户取消后如何清理动作队列？

---

### P-004 上层规划正常，底层控制仍一卡一卡

**面试问法**：感知和 VLA 只有几赫兹，机器人伺服要求更高频，系统怎么工作？

**现象**：上层规划一段时间没有更新，底层控制器不知道如何插值或跟随；控制命令周期不稳。

**根因链**：混合不同时间尺度，却没有目标缓冲、过期检查和本地跟踪。

**排查顺序**：按层记录频率、延迟和时效；检查控制器是否阻塞等待上层；检查队列是否积压。

**处理方法**：上层输出带时间戳目标或动作块；本地控制高频跟踪；不同层独立超时和降级；下层只执行新鲜目标。

**面试回答**：实时系统按信息变化速度和物理带宽分层。高层低频、底层高频，中间用时间戳与动作块衔接。

这也是快慢系统的基本分工：慢层选择任务或技能，快层负责连续动作和安全跟踪；快层目标过期时应停止或降级，不能无限执行旧目标。

**追问**：

- 为什么让 VLA 直接控制每个伺服周期不现实？
- 动作块过期后控制器应继续还是停？

---

### P-005 消息都在发，关键控制却延迟或丢失

**面试问法**：ROS 2 的 Topic、Service、Action 怎么选？

**现象**：用 Topic 发送长任务结果丢失，用 Service 等待长操作阻塞，用无界队列导致旧命令堆积。

**根因链**：连续传感器、短请求和长任务使用了不合适的通信方式；消息可靠性、队列深度、保留时间和超时也没有按控制时限设计。

**排查顺序**：检查发布频率、消息大小、网络 QoS、订阅方、队列和延迟；对比共享内存与网络传输。

**处理方法**：连续传感器与控制常用带时效 Topic；短请求用 Service；长任务用可反馈可取消 Action；大消息评估共享内存；关键路径测最坏延迟。

**面试回答**：ROS 2 组件选择依据是通信语义和时限。实时性来自端到端测量、调度和资源隔离，不能仅由 Topic 名字保证。

**追问**：

- 可靠 QoS 为什么可能增加延迟？
- 消息队列为什么不能无限深？

---

### P-006 服务在开发机能跑，换环境就找不到依赖

**面试问法**：主机上脚本正常，为什么远端用户、另一台机器或另一个 GPU 环境不能直接运行？

**现象**：环境变量、解释器、CUDA、Python 包、模型缓存、配置、权限、网络地址或工作目录不同；同一任务在一台机器可用，换用户或远端后启动失败。

**根因链**：启动依赖隐式继承本地 shell；远端和主机分别维护配置；运行身份、依赖和模型资产没有被一起锁定。

**排查顺序**：

1. 比较解释器、依赖、CUDA、权限、配置和工作目录。
2. 检查模型、norm 和 tokenizer 是否来自同一版本。
3. 检查远端环境变量是否被本地 shell 意外展开或丢失。
4. 模拟另一个用户和另一台机器的启动路径。
5. 确认服务出错时给出明确依赖错误，而不是假 READY。

**处理方法**：启动器只向远端传递必要显式参数；锁定解释器、依赖、CUDA 和资产；使用容器或固定运行环境；原则是最小权限并隐藏凭据。

**面试回答**：SSH 能登录不等于机器人服务可运行。可部署系统需要显式、可复原的运行环境和资产契约，开发机成功不能证明跨机可复现。

**追问**：

- 为什么远端脚本必须自己检查模型、相机、依赖和 CUDA？
- 环境变量经 SSH 转发时如何避免本地 shell 先展开？
- 容器镜像相同仍可能缺少哪些运行条件？

---

### P-007 一个任务报错，整个机器人系统一起失去可用性

**面试问法**：模型服务出错为什么不能让遥操作也失效？

**现象**：模型进程崩溃后，Agent、控制客户端和人工接管都不可用；端口或 GPU 异常扩散。

**根因链**：服务与安全控制同进程；共享故障域；没有超时降级与独立人工入口。

**排查顺序**：梳理依赖关系；模拟模型服务、网络、相机和 Agent 各自故障，检查系统还能做什么。

**处理方法**：推理、控制、安全和人工接管故障隔离；独立超时；模型不可用时禁自主但保遥操作；明确降级状态。

**面试回答**：故障隔离的目标是失效时仍可安全停止或人工接管。模型与 Agent 不应成为人工安全的单点依赖。

**追问**：

- 模型不可用时仍可以执行哪些低风险动作？
- 降级状态如何通知用户？

---

### 部署现象题答题框架

1. 画出请求、会话、模型、动作队列、控制器和 ROS 发布链。
2. 确定每个状态和资源的唯一所有者。
3. 检查 metadata、时效、取消、失败和重试语义。
4. 检查依赖、进程、端口、锁和故障隔离。
5. 通过日志与动作追踪重建一次完整执行。

### 一页总结

部署题不是列组件名，而是解释“谁拥有控制、数据怎样在哪些状态之间移动、失败时哪一层能安全停止或降级”。消抖、显存、版本、动作布局和真机故障的具体根因见[跨模块故障题](#cross-module)。

### I-001 离散动作模型只能慢慢吐 token

**面试问法**：OpenVLA 或 RT-2 式动作 token 为什么会限制控制频率？

**现象**：视觉编码不慢，但动作 token 依次生成，串行解码和网络响应增加延迟。

**根因链**：动作被量化到离散 token，自回归生成逐 token 依赖前一个；大模型复算与命中缓存需要管理。

**排查顺序**：测视觉 prefill、每个 token 解码、动作反量化和总请求；检查词表和动作维度；比较动作块长度。

**处理方法**：KV cache；并行解码或连续动作头；动作 tokenizer 压缩动作块；蒸馏与小模型；量化与专用后端。

**面试回答**：离散动作复用语言模型语义能力，但自回归串行和量化会限制高频控制。加速必须同时验证连续性和闭环成功。

**追问**：

- 动作 token 压缩率与推理加速为什么不是同一个指标？
- 连续动作头为何可能更实时，但更易多峰平均？

---

### I-004 控制周期平均正常，偶尔超过 deadline

**面试问法**：机器人明明能跑 20 Hz，为什么偶尔卡顿？

**现象**：平均周期达标，但 p95、最大值和抖动超出控制允许范围，偶尔耗尽动作队列。

**根因链**：CPU 调度、锁、GC、网络、日志和模型推理竞争；实时性看尾部而不是均值。

**排查顺序**：测控制线程、编码线程、模型线程和网络的时间分布；检查优先级、锁共享和内存分配。

**处理方法**：关键控制线程隔离；有限队列；工作移出控制循环；deadline、超时和降级；压力测试。

**面试回答**：实时系统的目标是少超时，而不是平均跑得快。必须报告 p95、p99、超时率和最长连续超时。

**追问**：

- 实时内核为什么不自动保证应用实时？
- 什么操作会导致控制线程偶发长暂停？

---

### I-005 控制频率变化后，原来稳定的 PID 参数开始振荡

**面试问法**：同一组 PID 参数在旧控制频率下稳定，为什么提高发布频率或改变传感器周期后反而振荡？

**现象**：控制目标并未改变，控制器参数也未变，但控制周期、采样频率或执行延迟变化后，系统出现高频摆动、过冲或持续校正。

**根因链**：离散控制积分与微分对采样周期敏感；速度估计、滤波器、通信和执行延迟改变闭环相位；旧频率下稳定的增益在新时序下不再稳定。

**排查顺序**：

1. 核对控制频率、采样时刻和实际执行延迟。
2. 比较原始目标、控制器输出和关节反馈。
3. 分别关闭积分、微分和滤波看稳定性。
4. 检查速度估计使用的周期是否随控制频率更新。
5. 在空载和带载条件下复测。

**处理方法**：按真实采样周期重调控制器；修正速度估计和滤波；统一通信、执行和状态时间戳；必要时使用增益调度、LQR 或 MPC，而不是只改 P 增益。

**面试回答**：控制器是在离散时间中执行，积分、微分、滤波器和延迟都依赖采样周期。频率改变后应从闭环时序和状态估计重调，而不是把振荡全归因于模型动作。

**追问**：

- LQR 和 MPC 对控制周期的要求有何不同？
- 为什么平均控制频率正常仍可能因抖动而不稳定？

---

### I-006 自由空间动作正常，接触后力过大或滑脱

**面试问法**：抓取、擦拭和装配为什么需要柔顺控制？

**现象**：位置控制到点后压坏物体或直接弹开；位置略偏时夹取滑脱。

**根因链**：位置误差不能表达期望接触力；工具重力、接触摩擦和传感器延迟未补偿。

**排查顺序**：检查力传感器零点和标定；比较位置目标与实际接触；改变阻抗刚度/阻尼；测量控制环延迟。

**处理方法**：阻抗、导纳或力位混合控制；力反馈与工具重力补偿；接触阶段切换；限力与安全监控。

**面试回答**：接触任务需要同时约束位置与力。阻抗/导纳改变机器人与环境的动态关系，比单纯位置误差更合适。

**追问**：

- 阻抗和导纳的输入输出有何不同？
- 高刚度为什么可能使接触不稳定？

---

### I-007 低频状态融合高频 IMU 后反而抖动

**面试问法**：多传感器融合为什么会让估计更差？

**现象**：IMU 积分漂移，视觉/LiDAR 更新时跳变，融合后的姿态抖动。

**根因链**：坐标系、单位、时间戳和噪声模型不一致；延迟与协方差不准确。

**排查顺序**：检查每个传感器原始频率和延迟；做静态零偏；比较预测与更新残差；验证时钟。

**处理方法**：统一坐标系和时间；滤波状态与噪声建模；异常测量拒绝；延迟补偿或缓冲。

**面试回答**：融合的前提是有正确的观测模型和时序。高频不等于准确，低频也不等于无条件可信。

**追问**：

- 卡尔曼滤波的预测和观测更新各起什么作用？
- 为什么 IMU 单独长时间积分会漂移？

---

### I-008 地图和定位都有，轨迹仍随时间漂移

**面试问法**：SLAM 系统为什么必须有回环或重定位？

**现象**：短距离定位良好，长路径误差累积；重新回到旧位置时地图与轨迹对不上。

**根因链**：局部里程计累积误差；回环检测缺失；后端优化未使用全局约束。

**排查顺序**：查看轨迹误差、回环事件和位姿图残差；比较静置与运动、室内与室外；检查动态物体。

**处理方法**：视觉/激光里程计；回环检测；因子图优化；重定位；多传感器约束。

**面试回答**：SLAM 是联合估计轨迹与地图。回环把历史地点重新关联以抑制漂移，评估必须包含长路径和重定位。

**追问**：

- 视觉与 LiDAR SLAM 在什么环境下各有弱点？
- 地图会过期时导航如何避免旧障碍？

---

### I-009 全局路线可达，局部还是撞到障碍

**面试问法**：全局规划已经给出路线，为什么还会碰撞？

**现象**：地图上的路线无碰撞，但动态障碍、机器人足迹、定位误差或局部控制使路径不可执行。

**根因链**：全局规划粒度粗；局部避障没有实时感知；代价地图和膨胀不匹配真实几何。

**排查顺序**：检查地图时效、机器人体积、成本地图和实时传感器；固定目标比较全局与局部轨迹；测试窄通道。

**处理方法**：全局规划；局部控制器；障碍膨胀与安全距离；重新规划；动态障碍感知；速度限制。

**面试回答**：全局解决可达，局部解决当前执行安全。不能通过简单缩小障碍膨胀来通过窄道，必须验证碰撞余量。

**追问**：

- A*、Dijkstra、RRT 的取舍是什么？
- 为什么定位误差必须计入障碍安全距离？

---

### I-010 语言目标能识别，长距离导航仍迷路

**面试问法**：VLN 与 ObjectNav 为什么比短程视觉操作难？

**现象**：模型能识别物体或理解简单指令，却在多房间、遮挡、关系描述和长路线中走错。

**根因链**：需要语言关系、空间地图、探索、定位和连续控制；单帧语义不足。

**排查顺序**：把任务拆成语言理解、目标检测、空间关系、探索、规划与执行；检查每层 success；比较仿真和真实地图。

**处理方法**：语义地图；前沿探索；分层规划；VLN 数据集；闭环重定位；置信度与重新观测。

**面试回答**：语言理解只解决目标含义，实际导航还要探索、记忆空间关系和执行控制。长程误差应分层评测。

**追问**：

- VLN 的成功率和路径效率分别说明什么？
- 开放词汇检测幻觉如何影响导航安全？

---

### I-011 人形或四足身体平衡，手臂任务却无法执行

**面试问法**：WBC 为什么需要多个任务优先级？

**现象**：腿足机器人维持平衡，但末端定位不准；手部目标与脚底接触冲突时身体抖动。

**根因链**：浮动基座、接触力和全身耦合；多任务目标可能矛盾。

**排查顺序**：检查接触状态、身体状态估计、任务优先级、关节限位和末端可达性；比较固定基座与浮动基座。

**处理方法**：MPC 预测、WBC 约束、零空间投影、接触规划、RL locomotion 与安全优先级。

**面试回答**：腿足与操作是全身耦合问题。平衡和接触安全高于末端非关键任务，动作必须满足摩擦和支撑约束。

**追问**：

- WBC 与 MPC 如何分层？
- 为什么末端任务优先级不能高于平衡约束？

---

### I-012 人体动作重定向后机器人不自碰撞就能执行

**面试问法**：遥操作看起来像人，为什么机器人动作不可执行？

**现象**：重定向后的骨架与人相似，但机器人关节不可达、自碰撞或脚滑。

**根因链**：人体与机器人尺寸、自由度、质量不同；重定向只求视觉相似，没求动力学可行。

**排查顺序**：检查关节限位、碰撞、末端可达、接触和速度；对重定向目标做 IK；比较视觉和动力学目标。

**处理方法**：运动重定向、IK、碰撞检测、速度限制、平衡约束和可执行轨迹重规划。

**面试回答**：重定向要同时满足语义相似和机器人物理约束。视觉上像人不足以证明运动安全。

**追问**：

- 上身与下身解耦控制有什么取舍？
- 为什么遥操作延迟会诱使操作者过度修正？

---

### 推理控制现象题答题框架

1. 画出观测、推理、动作块、队列、发布、控制器和关节反馈的时间线。
2. 分别看模型原值、后处理值、命令和实际反馈。
3. 区分延迟、抖动、漂移、回跳、错位和接触失败。
4. 控制问题先用预设轨迹隔离模型。
5. 处理方案要说明速度、延迟、平滑、安全和恢复代价。

### 一页总结

推理控制题的核心是实时执行。模型输出必须经过时效、归一化、动作语义、连续性和安全约束，底层反馈才是最终证据。消抖、超时、布局、导航摇摆、IK、显存与版本故障的完整主答统一在[跨模块故障题](#cross-module)。

## 5. 跨模块工程现象题库


这一节不按“数据、训练、部署、推理”分章，而按**真实现象**组织。很多面试题换了一个模块名称，实际上问的是同一条工程链路。

例如“机器人抖动”可能来自：

- 数据中的异常动作和错误时间同步。
- 策略采样随机性过大。
- 动作块新旧接缝不连续。
- 推理波动导致旧动作过期。
- 多线程重复消费或缓存回写。
- 滤波参数、控制器增益或机械接触问题。

一个简单的跨层例子：

- 数据层：动作和图像时间错位。
- 训练层：模型学到错误延迟补偿。
- 部署层：相机顺序与训练不一致。
- 推理层：动作块接缝没有按实际执行进度续接。
- 控制层：PID 或阻抗参数把残余误差放大。

现象都可能是“机器人抖动”，但修复方式完全不同。下面每一题都强调先定位，再处理。

只回答“加一个低通滤波”远远不够。高质量答案应先定位现象属于哪一层，再解释处理手段和副作用。

### 这一节怎么使用

先按故障现象查找；每个条目都尽量回答五层：

1. 现象和常见误判。
2. 从数据到物理执行的时间线。
3. 哪些模块可能产生同一种症状。
4. 应做哪些可证伪检查，而不是直接扩大阈值。
5. 处理后的副作用和安全恢复条件。

同一故障可能跨多个模块。面试时应该先提出分层验证，再给出最可能的根因和修复。

### G-001 机器人持续消抖：同一现象为什么有六种根因

**面试问法**：机器人动作一直抖，先调滤波器还是先查别的？

**高质量结论**：先判断抖动发生在“模型原始输出、动作块拼接、调度时序、控制命令、实际关节反馈还是机械结构”哪一层。低通滤波只能处理其中一部分。

#### 第一层：模型输出本身抖动

现象：固定观测、固定历史，但多次推理动作差异很大。

可能原因：

- 生成式动作头每次随机采样不同。
- 推理步数太少，动作还未收敛。
- 温度、噪声尺度或随机种子不稳定。
- 多帧历史正在变化，模型条件本身不同。
- 动作损失和辅助目标训练不充分。

验证方法：冻结随机种子、固定输入和历史，比较多次输出；关闭随机采样，观察是否仍抖。

处理手段：控制采样随机性、调整生成步数、提高动作平滑似然或使用确定性推理。代价是可能损失动作多样性，也可能掩盖模型不确定性。

#### 第二层：新旧动作块拼接不连续

现象：动作块内部平滑，但一到重规划附近出现回跳、停顿或加速。

可能原因：

- 新动作块从旧观测的起点开始，而机器人已经执行了一段。
- 新旧动作块坐标系、归一化或维度布局不一致。
- 根据时间估计对齐，但推理耗时变化导致位置偏差。
- 两个块中间残留直流偏置，普通低通去不掉。

验证方法：关闭模型，只回放两段已知动作；检查接缝处的关节位置、速度和加速度差。

处理手段：

- 按实际已执行动作或当前机器人状态寻找新块的匹配起点。
- 新动作第一帧对齐到最近已执行动作。
- 在有限步数内衰减连续性偏置。
- 把已执行动作作为条件，让新块从当前进度续写。

**为什么不能只靠低通**：低通会削弱高频变化，却不能保证新块和旧块在同一个绝对位置上。大的位置阶跃即使经过滤波，仍可能造成减速、滞后或长尾漂移。

#### 第三层：调度和时序抖动

现象：模型输出稳定、回放动作稳定，但实时运行时发布间隔不均匀。

可能原因：

- 推理与主控制循环争 CPU。
- 线程锁、日志、序列化和图像编码阻塞。
- 推理时快时慢，但动作仍按固定频率消费。
- 多个推理结果互相覆盖，或线程检查存在竞态。
- 网络尾部延迟远大于平均延迟。

验证方法：同时记录请求开始、返回、进入缓冲区、被消费和实际发布的时间；计算间隔的 p95 和最大值。

处理手段：有限队列、在途请求标志、看门狗、优先级隔离、后台编码和固定频率发布。注意：单飞行请求限制可以防止 WebSocket 响应错位，但可能导致请求饥饿，仍需超时和恢复策略。

#### 第四层：动作后处理与控制参数

现象：模型动作合理，但经过后处理后变得迟钝或振荡。

可能原因：

- 截止频率与发布频率不匹配。
- 滤波阶数过高，引入明显延迟。
- 位置、速度、夹爪和底盘使用了同一套参数。
- 平滑窗口过短而无效，或过长造成滞后。
- 门限、死区和缩放参数改变动作幅值。

验证方法：叠加显示原始动作、处理后动作、实际关节反馈；分别关闭滤波、连续性偏置和缩放做消融。

处理手段：按动作语义分别滤波；检查截止频率、采样频率和延迟；先修拼接，再决定是否需要滤波。

#### 第五层：底层控制器和状态估计

现象：命令已经平滑，关节反馈仍振荡。

可能原因：

- PID 比例或微分增益过高。
- 积分饱和、输出限幅或模式切换没有重置。
- 速度、加速度前馈与机器人动力学不匹配。
- 阻抗过刚或力传感器滤波延迟。
- 状态估计抖动，控制器跟踪了错误的反馈。

验证方法：用离线或预设平滑轨迹绕过模型；观察命令与编码器反馈、速度估计和力矩曲线。

处理手段：重新辨识负载与延迟，调整控制增益，增加速度或加速度约束，修正状态估计和力补偿。

#### 第六层：机械与环境

现象：控制链路都稳定，但机器人本体仍发出振动或末端抖动。

可能原因：

- 减速器背隙、柔性、关节摩擦或结构共振。
- 末端负载改变惯量。
- 相机支架松动导致视觉抖动。
- 接触冲击和物体滑动反馈到控制。
- 车身移动造成轮速、IMU 和关节同步误差。

验证方法：固定相机和负载做重复测试，对比静止、空载、带载和接触状态；查看振动频谱和机械装配。

处理手段：机械紧固、减振、负载补偿、速度限制和接触控制。纯算法滤波不能修复松动的机械结构。

#### 滤波不是一种固定方法

工程里常见的“平滑”至少有四类：

- **连续在线低通**：只用过去数据，适合实时跟踪，但会引入相位延迟。
- **前后向滤波**：使用整段未来动作，适合离线动作块或已生成轨迹，不适合把未来数据当成实时观测。
- **连续性偏置**：解决新旧块绝对位置不一致，主要修正直流偏移。
- **插值或时间混合**：把一个目标平滑过渡到另一个目标，常用于模式切换和队列接缝。

面试官如果问“为什么都是平滑却效果不同”，应回答它们作用的信号、因果结构和目标不同。前后向滤波的零相位不等于在线零延迟；零相位也不代表不会未来化。

#### 动作越界处理为什么会留下长期偏差

直接把每步输出裁剪到局部上下界，可能每步都只差一点，但误差会持续存在；如果动作依赖当前绝对状态，这种偏差还会改变后续观测和动作分布。裁剪适合异常拦截，不能随意代替全局规划、控制器限速和轨迹可行性检查。

#### 为什么不能把减速当成停止

减速可以继续使用一小段安全轨迹并降低速度，但仍需要新鲜观测和剩余时间；停止则清空队列并放弃后续动作。高风险场景优先停止，允许安全降级时也要有明确最大持续时间和速度约束。

**30 秒面试回答**：抖动不是单一算法问题。我会先比较模型原始输出、动作块接缝、命令发布时序、实际关节反馈和机械响应。模型随机性用固定输入与随机流排查，接缝问题用实际位姿对齐和连续性衰减，时序问题看 p95 尾部延迟、控制周期抖动与队列耗尽，控制问题比较命令和实际反馈，机械问题检查负载与共振。滤波只在确认是高频噪声后使用，并说明截止频率、相位延迟、采样频率和夹爪例外。

**追问**：

- 低通滤波为什么会让动作更平滑，却增加响应延迟？
- 为什么越界处理后的位置偏差可能长期不消失？
- 前后向滤波为什么会改变因果实时性？
- 为什么夹爪不宜与连续关节共用同一套平滑参数？
- 如何证明抖动来自模型采样而不是控制？

### G-002 动作块切换时回跳、卡顿或突然加速

**面试问法**：模型每 0.5 秒重规划一次，为什么机器人总在新旧动作之间来回？

**根因链**：旧观测 → 推理耗时 → 机器人已执行若干步 → 新块仍从旧起点开始 → 新旧轨迹不连续。

**排查顺序**：

1. 记录推理期间已消费动作数。
2. 检查新块从第几步开始接入。
3. 比较新块搜索窗口与当前实际关节状态。
4. 检查新旧块是否共享同一归一化与动作布局。
5. 检查接缝处是否存在无法被低通消除的固定位置差。
6. 确认任务切换后旧块已经清空。

**处理方法**：运行进度对齐、实际状态匹配、动作前缀条件、连续性偏置、有限队列和任务代次。

**常见误区**：只对拼接后的整段动作做平滑。平滑会让接缝看起来不尖，但可能保留整体回退或导致响应变慢。

**面试回答**：先用时间对齐确定新块应从哪一步接续，再用实际状态或已执行动作校正起点，最后才做局部连续性处理。动作块重规划的核心不是滤波，而是新旧轨迹的时间与状态对齐。

### G-003 推理变慢后仍执行旧动作

**面试问法**：网络从 100 毫秒突然抖到 1 秒，机器人应该继续用完动作队列吗？

**真实风险**：旧动作在旧视觉条件下合理，但当前环境可能已经改变。长时间继续执行会撞到新出现的人或物体。

**处理原则**：

- 动作必须带观测时间、生成时间和任务代次。
- 设置最大观测年龄、队列最大剩余时间和推理超时。
- 在旧动作剩余不足安全窗口时提前重规划。
- 超时则暂停、清队列、要求新观测并重新武装。
- 在速度与风险允许时，可保留极短、已审计的动作进行安全减速。

**面试追问**：为什么“推理结果还没超时”不等于“观测还新鲜”？因为观测可能在请求发出前就已经延迟，推理完成时条件更旧。

**面试回答**：实时机器人需要同时限制动作年龄和总推理延迟。超过安全窗口应停止消费旧轨迹，而不是为了运动连续而无限延长。

### G-004 动作被重复执行、跳步或队列饥饿

**面试问法**：控制频率固定，为什么同一个动作有时执行两遍，有时直接跳过？

**根因**：生产者和消费者索引不一致；新结果覆盖旧缓冲区；任务切换后索引未重置；并发读取时同一帧被多个线程消费。

**需要区分的三种情况**：

- **重复消费**：读取索引没有前进，同一动作在多个控制 tick 发出。
- **跳步**：新块一次替换整段队列，索引却指向更远位置。
- **饥饿**：新推理过慢，旧队列耗尽，控制循环没有动作可发布。

**处理手段**：动作唯一编号、原子索引、单消费者、剩余长度监控、预取阈值和推理超时。

**面试回答**：队列需要明确所有权和消费语义。每个控制 tick 只能消费一次，重规划要从当前执行进度续接；耗尽必须显式降级或停止，不能静默保持最后一条命令。

### G-005 监控显示正常，但机器人完全不动

**面试问法**：推理请求成功、延迟正常、WebSocket 在线，为什么机器人没动？

**排查链**：

1. 模型是否收到当前任务和当前观测。
2. 模型输出是否有限值、形状和维度正确。
3. 动作是否进入客户端队列。
4. 队列是否被消费。
5. 安全门是否暂停、限幅或清空动作。
6. 客户端是否真的发布控制命令。
7. 控制器是否收到，是否存在其他发布者抢占。
8. 机器人是否处于使能、复位或急停状态。

**关键认识**：服务健康、推理健康和物理执行健康是三个不同指标。

**面试回答**：先证明整条链，而不是重新训练模型。至少要有请求、输出、队列消费、命令发布、控制器接收和关节反馈六类证据。

---

### G-006 服务已就绪，第一次任务仍长时间卡住

**面试问法**：端口已经监听、warmup 也打印成功，为什么首个真实请求还是慢？

**常见原因**：

- 预热输入形状和真实相机、历史帧数量不同。
- 只预热了零延迟分支，没有覆盖其他动作前缀长度。
- 推理后端在首次遇到新 mask 或输入长度时重新编译。
- 图像解码或预处理在首个请求才分配大缓存。
- 模型 ready 了，客户端和相机还没 ready。
- 多服务同时完成预热，真实请求到来时争抢显存和计算。

**处理手段**：用生产同形状输入覆盖所有 TTC 分支，记录固定输入指纹，预热编码与预处理，并把服务、相机、客户端和控制器分别就绪。

**面试回答**：就绪状态必须覆盖请求实际使用的所有形状和延迟分支，并包含端到端依赖。端口监听只是最小条件。

---

### G-007 单步动作突变后暂停，恢复仍不安全

**面试问法**：客户端发现相邻命令变化超过阈值后暂停，为什么不能直接按恢复键继续？

**风险**：暂停期间机器人、物体或场景可能已经变化；旧动作历史不再代表当前状态。

**正确流程**：

1. 检测到异常命令后停止消费和发布。
2. 清空旧动作队列、待应用结果和前缀条件。
3. 获取新的多相机、关节和时间戳。
4. 检查其他控制发布者是否仍在写命令。
5. 重新请求动作并与当前实际状态对齐。
6. 由操作员明确确认后重新武装。

**常见误区**：把阈值调大“避免误停”。门限过大可能放过真正危险跳变；门限过小又会误停真实快速动作。

**面试回答**：动作突变是安全触发器，不只是滤波器输入。暂停后必须清状态、重新观测和显式恢复，不能继续旧缓存。

---

### G-008 人工接管后模型继续抢控制权

**面试问法**：操作员接管时模型没有完全停止，会出现什么问题？

**真实风险**：两个控制源同时发布，命令快速交替，造成抖动、关节负担和操作员误判。

**设计要求**：

- 控制所有权必须独占。
- 人工命令出现后立即暂停模型输出。
- 人工释放后不能自动恢复，应重新确认状态。
- 同一命令主题存在多个发布者时要告警。
- 暂停只阻止新动作不够，还要清空旧队列。
- 接管期间禁止任务切换和自动重试。

**面试回答**：控制所有权是系统安全边界。模型和人工不能共享关节写权限；接管是整个会话的状态变化，必须覆盖队列、前缀、历史和恢复确认。

---

### G-009 切换任务后执行了上一个任务的动作

**面试问法**：用户从“拿杯子”切到“导航”，为什么机器人先做了旧任务动作？

**根因**：旧请求仍返回；缓存未清；任务版本未校验；动作队列未按会话隔离。

**处理手段**：任务代次、请求编号、会话标识、切换时取消或忽略旧响应、清空动作与历史。

**面试回答**：每次任务切换都是新会话。响应必须带回代次，客户端只接受当前代次；旧任务的动作、队列、TTC 前缀、完成信号和观测历史全部失效。

---

### G-010 新 episode 继承了旧画面和动作历史

**面试问法**：机械臂复位后第一帧仍受上一回合影响，可能是什么原因？

**根因**：服务端和客户端历史缓存跨 episode 保留；多帧缓存没清；KV 或 prefix 条件未重置；旧图像仍留在队列。

**正确做法**：episode 边界同时清本地相机历史、服务端观测缓存、动作队列、TTC 前缀、完成状态和请求代次。

**面试回答**：episode reset 是端到端状态清除，不只是清 loss 或计步。多帧模型尤其要保证第一帧只看到新回合数据。

---

### G-011 相机偶发无图、黑屏或重复帧

**面试问法**：相机 topic 还在，但模型偶尔效果很差，如何定位？

**分层排查**：

- 采集：曝光、驱动、设备断连。
- 传输：丢包、延迟、压缩失败。
- 解码：格式错误、颜色转换、尺寸异常。
- 缓存：重复最近帧、旧帧未过期。
- 预处理：全零、裁剪错误、去畸变异常。

**处理手段**：保存原始与处理后图像、时间戳、字节大小、帧编号和校验；对黑帧、尺寸和延迟设置明确失败；不要用重复旧帧假装当前。

**面试回答**：topic 存在不代表帧有效。要检查帧新鲜度、内容、尺寸、编号和相机时间，并区分采集故障与模型故障。

---

### G-012 各路传感器都在发，但视觉和动作错位

**面试问法**：多线程都有数据，为什么训练或真机仍学不到正确动作？

**根因**：按到达顺序而非采集时间配对；设备时钟不一致；图像解码延迟大；动作在视觉之前或之后执行；网络积压后旧帧被当成新帧。

**处理手段**：原始时间戳、统一时钟、允许时间窗、过期丢弃和缺帧遮罩。关键状态和控制命令也应带时间。

**面试回答**：同步目标是匹配语义时间。只比较平均帧率或数组长度没有意义。

---

### G-013 模型输出形状正确，机器人却朝错误方向动

**面试问法**：动作维度都是 22，为什么不能直接互换？

**常见语义差异**：

- 关节顺序或左右臂顺序不同。
- 绝对值与增量动作混淆。
- 夹爪零点与开合方向不同。
- 关节角度与末端位姿混用。
- 训练归一化范围和部署范围不同。
- padding 维被当成有效动作输出。

**排查手段**：单维小动作测试、逐关节限幅、动作布局哈希、归一化统计版本、动作方向表。

**面试回答**：动作维度相同不等于动作语义相同。先校验布局、单位、绝对/增量、夹爪和 norm，再讨论模型质量。

---

### G-014 夹爪抖动、延迟开合或持续夹紧

**面试问法**：为什么平滑参数对机械臂有效，对夹爪反而有害？

**原因**：夹爪接近离散状态，过强低通会造成开合延迟；阈值附近抖动会让模型反复开合；偏置和缩放会改变物理行程。

**处理手段**：夹爪单独设置死区、滞回、变化率和上下界；验证开合方向与标定；对近离散动作采用状态切换而不是关节式滤波。

**面试回答**：夹爪控制要保留离散语义并加滞回。与连续关节共用平滑和偏置会导致夹取时机错误。

---

### G-015 模型很久不报完成，或任务未完成就停止

**面试问法**：任务完成概率达到阈值，为什么还要继续检查？

**原因**：完成头训练分布有限；单一高值可能是噪声；固定执行时长和模型概率都可能错。

**处理手段**：连续多次阈值、进度、视觉状态、夹爪/物体位置、硬超时、人工验收和安全停止共同判断。

**面试回答**：模型完成概率只是信号之一。生产系统需要物理验收与超时，不能在概率首次超过阈值时盲目停止。

---

### G-016 Agent 工具返回成功，但物理任务失败

**面试问法**：MCP 工具返回 success，为什么不能说任务完成？

**原因**：success 可能仅表示请求已发送、进程退出码为零或动作播放完毕，不代表物体到达目标。

**处理手段**：工具结果区分“已接收、执行中、已结束、物理验收通过、失败、取消”；Agent 需要检查观测和任务里程碑。

**面试回答**：工具契约必须区别命令 ACK 和世界状态成功。物理任务要在工具外或工具内做明确验收。

---

### G-017 末端目标合理，机械臂却不可达或速度爆炸

**面试问法**：模型给出一个末端位姿，为什么不能直接执行？

**原因**：目标不在工作空间；IK 多解选择错误；接近奇异点；碰撞；相邻解跳变；关节限位。

**处理手段**：IK 可行性、关节限位、碰撞检查、多解连续性、阻尼最小二乘、奇异点降速和路径检查。

**面试回答**：末端空间动作必须经过运动学与安全校验。单个终点可达不代表从当前位姿到终点的插值路径可行。

---

### G-018 模型动作平滑，底层关节仍高频振荡

**面试问法**：怎样证明问题不在 VLA？

**验证方法**：用预设平滑轨迹绕过模型；对比命令和反馈；降低或关闭积分项；检查速度估计与滤波延迟；改变负载和姿态重复。

**可能原因**：PID 增益、积分饱和、速度噪声、阻抗参数、机械共振和执行器延迟。

**面试回答**：当权威平滑轨迹仍产生振荡，问题已进入控制或机械层。模型层继续调参没有证据。

---

### G-019 导航直行左右摇摆，或到点后持续修正

**面试问法**：导航振荡应该先改全局规划还是局部控制？

**根因拆分**：

- 全局路径频繁变化。
- 局部控制器角速度增益过高。
- 定位跳变。
- TF 或里程计漂移。
- 轮子打滑、底盘参数或控制延迟。
- 到达容差太小，持续来回修正。

**排查顺序**：固定全局路径 → 固定定位与 TF → 记录目标、控制输出和实际轨迹 → 再调局部控制。

**面试回答**：导航摇摆可能是规划、定位或底盘控制的组合。先固定上游输入，确认局部控制器对静态路径是否稳定，再逐层放开。

---

### G-020 TF、定位和地图看似存在，机器人仍走偏

**面试问法**：所有 topic 都有数据，怎样发现坐标问题？

**检查点**：TF 时间是否最新；地图、基座、相机和末端坐标关系是否正确；外参版本；定位跳变；地图与原环境是否同代；雷达/相机时间是否对齐。

**面试回答**：坐标树存在不代表变换可信。要验证时间、方向和尺度的端到端一致性，例如用固定地面点或标定目标检查。

---

### G-021 开放词汇模型总能看到不存在的物体

**面试问法**：VLM 或开放词汇检测在导航中产生幻觉怎么办？

**原因**：文本相似不等于空间存在；单帧误检；遮挡与光照；地图旧实例；缺乏多视角一致性。

**处理手段**：置信度阈值、多次观测、几何一致性、时序跟踪、语义地图投票、重新观测和安全距离。

**面试回答**：开放词汇能力提高了泛化，但必须把语言置信度与物理证据结合，不能让一次检测直接驱动运动。

---

### G-022 多模型启动时 GPU 突然显存不足

**面试问法**：每个模型单独运行都够，为什么一起启动会 OOM？

**原因**：权重之外还有 CUDA 上下文、编译缓存、激活、图像缓存和多请求峰值；两个服务同时预热会叠加首请求峰值。

**处理手段**：测加载、编译和并发峰值；限制每卡模型数；串行预热；预留余量；清理失败进程；按需加载。

**面试回答**：显存预算按峰值而非静态权重。需要同时监控进程归属、CUDA 上下文和真实请求并发。

---

### G-023 端口空闲但进程反复启动失败或连错服务

**面试问法**：能连接端口是否说明目标服务正确？

**不一定**。可能连到旧版本、其他任务或残留进程。

**需要联合检查**：host、port、PID、命令、协议、metadata、模型版本、任务 prompt 和启动时间。

**处理手段**：PID 归属校验、协议握手、固定路由、独占租约和残留进程清理。

**面试回答**：端口只是网络端点。服务身份要由进程、metadata 和资产版本共同证明。

---

### G-024 进程杀掉后锁仍残留，机器人命令没有真正停

**面试问法**：进程不存在了，为什么新客户端仍说锁被占用，或者机器人还在动？

**可能原因**：文件锁由另一个进程持有；PID 文件过期；子进程仍活着；发布端未退出；控制队列仍在其他节点消费。

**处理手段**：识别锁所属进程；优雅终止并等待；验证子进程和命令发布者；检查关节反馈是否静止；必要时才强制终止并清锁。

**面试回答**：锁文件和机器人停止是两件事。停止证明需要进程、发布命令和实际关节状态三层证据。

---

### G-025 预热成功，正式请求却重新编译或数值变化

**面试问法**：如何证明 warmup 真的覆盖正式路径？

**方法**：记录请求形状、相机数量、历史帧、prefix 长度、数据类型、mask、后端和编译缓存；用生产同构 dummy 输入；保存固定种子输出指纹。

**常见原因**：只测零延迟；图像尺寸不同；真实 batch 或 mask 不同；编译缓存失效；换了精度或引擎。

**面试回答**：预热要覆盖模型契约的全部分支，并可复现输出；只看“warmup 没有报错”不够。

---

### G-026 权重能加载，真机动作却整体失真

**面试问法**：模型不报错，为什么动作误差系统性地大？

**重点检查**：归一化统计、动作 tokenizer、相机顺序和图像模式、状态与动作布局、增量动作遮罩、动作块长度、实时分块范围、任务描述和完成头。

**处理手段**：机器可读 metadata、哈希、启动前校验和固定输入回归。

**面试回答**：加载成功只证明结构兼容。模型行为还依赖整套训练契约，必须作为一个版本一起发布。

---

### G-027 精度或编译优化后输出看起来相近，真机成功率下降

**面试问法**：BF16、FP8、量化和编译是否可以直接上线？

**风险**：误差可能集中在接触边界、夹爪阈值、速度峰值和长时积分，单次平均误差看不出。

**验证手段**：同输入逐层和端到端比较；关键动作统计；固定种子回放；真机受控测试；长时闭环成功率。

**面试回答**：优化必须通过数值与闭环两层验收。单步动作接近不代表多步执行不漂移。

---

### G-028 相同配置训练结果无法重现

**面试问法**：固定 seed 为什么还不够？

**原因**：数据读取顺序、多卡随机状态、训练 dropout、动作采样、非确定性算子、断点恢复和采样进度发生了变化。

**处理手段**：分 rank 随机流、记录采样位置、数据配置和 norm、恢复 RNG、明确容差。

**面试回答**：可复现是数据顺序、模型初始化、生成随机性、并行归约和恢复状态的组合。

---

### G-029 Checkpoint 能加载，但无法正确继续训练

**面试问法**：只保存模型权重有什么问题？

**缺少内容**：优化器、学习率调度、EMA、采样位置、随机状态、混合精度状态、参数分片信息和训练步数。

**面试回答**：checkpoint 是完整训练快照，导出模型只是部署权重。恢复后要比较下一次 loss、采样索引和参数更新是否一致。

---

### G-030 少量坏帧导致 loss 尖峰或长期 NaN

**面试问法**：一个异常样本怎样毁掉整个 batch？

**原因**：动作或图像含 NaN；无效 mask 后仍做乘法；坏样本产生巨大梯度；异常值破坏归一化。

**处理手段**：有限值检查、维度和时间 mask、先选有效位置再归约、坏样本跳过、来源追踪、梯度监控和快速失败。

**面试回答**：先在数据层定位，再在损失构造和优化层设安全边界。长期 NaN 不能只靠降低学习率掩盖。

---

### G-031 训练 loss 下降，真机成功率不升

**面试问法**：为什么离线指标变好不等于策略变好？

**主要原因**：动作误差与闭环成功错配；训练分布泄漏；多峰动作被均值化；动作块开环过长；部署接口或 norm 不同；真机延迟。

**排查**：分层动作误差、生成质量、仿真闭环、受控真机和随机场景；比较原始与处理后动作。

**面试回答**：loss 是训练分布上的代理指标。真机成功需要闭环、时序、动作语义和安全执行共同验证。

---

### G-032 新任务学好了，旧任务突然退化

**面试问法**：后训练为什么破坏原能力？

**原因**：数据混合失衡、学习率过大、可训练参数过多、任务接口冲突和评测缺失。

**处理手段**：混合旧数据、参数高效微调、控制更新范围、任务分层评测和选择性回退。

**面试回答**：新任务提升与旧能力保持必须同时评估。不能只看新任务 loss 和少量成功样例。

---

### G-033 仿真成功，真机失败，到底差在哪

**面试问法**：Sim-to-Real 的排查顺序是什么？

**分层**：视觉外观 → 相机与时序 → 状态与动作接口 → 动力学与接触 → 执行器和延迟 → 任务评测。

**方法**：用真机日志回放仿真输入；先在另一仿真器做 sim-to-sim；做系统辨识；从小范围随机化到全范围；注入延迟和噪声。

**面试回答**：不要把 sim-to-real 当成一个总问题。先找出最接近真机接口的失败层，再逐层恢复仿真和真机差异。

---

### G-034 世界模型预测越来越平滑，控制却越来越差

**面试问法**：世界模型 loss 降低为什么可能不利于控制？

**原因**：过度预测常见静态状态；长时误差累积；忽略接触；隐表示丢失操作相关信息；训练分布外自信外推。

**验证**：分别评估短时/长时预测、接触事件、任务相关信息、闭环规划和真实恢复。

**面试回答**：世界模型需要评估控制所需信息，而不仅是视频重建或平均误差。预测平滑可能代表模型在回避不确定性。

---

### G-035 日志很多，仍无法判断动作来自哪次观测

**问法**：机器人动作追踪应该记录什么？

**至少包括**：请求、任务代次、会话、观测时间、模型版本、prompt、动作块编号、执行索引、安全处理、最终命令、接管和结果。

**面试回答**：日志要形成从用户意图到物理动作的因果链，而不是只记录模块异常。

---

### G-036 发布一半失败后模型、配置和控制器版本混用

**问法**：为什么重启全部服务不是可靠回滚？

**风险**：旧模型连新 norm、旧客户端连新协议、旧控制配置残留、动作队列跨版本、备份不可恢复。

**处理手段**：资产整体版本化、staging、灰度、健康检查、原子切换、回滚演练和配置哈希。

**面试回答**：版本单位应是完整契约，不是单个文件。回滚必须恢复模型、norm、相机、动作布局、客户端和控制配置的一致组合。

---

### G-037 自动重试没有解决问题，还产生了重复动作

**问法**：推理失败后应不应该自动重试？

**先区分错误**：瞬时网络错误、会话占用、观测过期、协议错误、模型输出非法、物理不可达。

**安全重试只适合幂等或可取消流程**。对已经发布部分动作的任务，重试前要确认执行进度、清旧结果并重新观测。

**面试回答**：重试应有错误分类、次数、时间预算和幂等条件。对物理动作不能简单重复发送同一命令。

---

### G-038 多个模型平均显存够，同时请求却崩溃

**问法**：为什么要测并发峰值？

**原因**：每个服务加载后常驻显存只是基线；编译、首请求、多帧历史、图像预处理和大 batch 会同时抬高峰值。

**处理方法**：串行预热、限制并发、按任务启停、预留缓存、监控碎片和失败后 GPU 释放。

**面试回答**：资源规划按同时活跃请求和最坏输入，而不是模型权重平均值。

---

### G-039 模型服务可用，但机器人端 CPU、网络或编码成为瓶颈

**问法**：模型很快，为什么端到端控制仍慢？

**瓶颈可能**：多路图像读取、压缩、序列化、网络、服务端解码、客户端锁、发布调度和日志。

**处理方式**：逐段计时、只发必需相机、并行编码、限制图像大小、控制线程隔离和背压。

**面试回答**：模型延迟只占端到端的一部分。实时系统必须看请求端到端的 p95、抖动和队列耗尽。

---

### G-040 只展示成功样例，无法证明系统稳定

**问法**：如何评测一个具身工程系统？

**至少分层**：单元契约、离线回放、仿真闭环、受控真机、随机场景、长时间运行、故障注入和人工接管。

**报告要包括**：成功率、失败类型、对象/场景分层、恢复率、延迟、安全触发、动作来源和置信区间。

**面试回答**：评测目标是暴露边界和失败模式，不是剪一段成功视频。成功样例不能替代统计结果与故障证据。

### 一页速答

**1. 消抖最先查滤波还是先查接缝？**
先定位。若块内稳定、块切换抖，应优先修对齐和连续性；滤波可能只是掩盖接缝。

**2. 低通滤波在实时系统里为什么可能不安全？**
会引入相位延迟，减小快速避障和接触修正能力；参数按离线回放并无考虑实时因果。

**3. 前后向滤波适不适合在线流？**
通常不适合直接作为因果在线滤波，因为它使用未来数据；离线动作块与实时发布要分开考虑。

**4. 为什么夹爪不能与关节共用平滑？**
夹爪近离散，平滑会延迟开合和夹取时机，应用死区、滞回和有限变化率。

**5. 为什么连续性偏置要逐渐衰减？**
首帧对齐消除接缝阶跃，持续偏置又会把新轨迹长期拉回旧状态，衰减兼顾连续和跟踪。

**6. 位姿对齐与时间估计有什么区别？**
时间估计假设执行速度和延迟准确，位姿匹配直接根据实际状态选择接续动作，更抗抖动。

**7. 自适应 horizon 为什么可能减少抖动？**
预测分歧较大时提前重规划，避免长时间执行失真轨迹；但重规划太频繁也会引入新接缝。

**8. 什么情况下应停止而不是平滑？**
动作越界、非有限值、观测过期、控制源冲突、推理超时和无法覆盖延迟时应停止并重新武装。

**9. 为什么推理慢不一定要扩大动作队列？**
扩大队列只会延长旧条件执行时间。应先降低推理延迟、提前预取或缩短模型路径，并为旧动作设年龄上限。

**10. 为什么只看平均推理延迟不够？**
控制稳定性由尾部延迟、抖动和队列耗尽决定，p95 与最大值更接近故障边界。

**11. 多线程推理如何避免重复请求？**
使用原子在途标志、请求编号和单消费者协议；看门狗超时后要处理旧连接和迟到响应。

**12. 为什么旧响应必须带任务代次？**
任务切换后返回的 actions 属于旧语义，客户端应拒绝而非与当前任务混用。

**13. 人工接管后为何不能自动恢复？**
机器人位置、物体和场景已改变，必须重新观测、校验独占权并由操作员确认。

**14. 单个服务正常为什么还会 OOM？**
多服务首请求和编译峰值叠加，CUDA 上下文和缓存也占资源。

**15. 端口可连接为什么不代表服务就绪？**
模型可能没预热、相机未就绪、metadata 和动作契约不匹配。

**16. 训练 loss 低为什么不能停止排查？**
真机成功还受时序、动作语义、闭环分布、动作块和控制器影响。

**17. 为什么 norm 单独更新会造成灾难？**
动作和状态尺度改变会让权重解释完全变化，即使模型结构正确。

**18. 为什么 checkpoint 和导出模型不能混用？**
前者是训练快照，后者是部署资产；二者配置、精度和附加头可能不同。

**19. Sim-to-Real 为什么先做 sim-to-sim？**
换物理引擎可在还不需要真机成本时暴露策略过度依赖单一仿真痕迹。

**20. 如何判断问题来自导航规划还是底层控制？**
固定规划输出只测跟踪，再对静态路径记录定位与实际轨迹；逐层替换上游输入。

### 工程现象题答题框架

遇到工程现象题，可以按以下顺序回答：

1. **现象定义**：不动、慢、抖、跳、偏还是假完成。
2. **时间线**：观测何时采集，请求何时发出，结果何时返回，动作何时执行。
3. **契约**：相机、状态、动作、norm、horizon 和任务代次是否一致。
4. **资源与并发**：是否有队列、锁、线程、GPU、网络和端口问题。
5. **控制与物理**：命令与实际反馈是否一致，机械与接触是否异常。
6. **安全处置**：先停止还是可降级，如何清状态和恢复。
7. **验证证据**：固定输入、回放、日志、消融和真机分层测试。
8. **副作用**：处理带来的延迟、滞后、安全距离、计算和运维成本。

### 复习方法

第一遍按现象读，理解同一故障可能跨越多层。第二遍遮住答案，用“时间线、契约、资源、控制、安全、验证”六步口述。第三遍结合自己的项目补一个具体数字和失败案例，但不要把内部实现细节直接泄露到公开笔记。

面试官真正想听的不是“用了什么库”，而是能否把现象拆开、提出可证伪的检查、采取安全处理，并用实验证明修复有效。

### 补充追问：从实现细节到面试追问

下面这些是面试官常用的第二、第三层追问，用来检查理解能否从“有这个模块”深入到“为什么这样做、失效时会怎样”。

#### 模型与调度

**为什么相同图像、相同状态，两次推理动作不一样？**
生成式动作头可能存在随机采样；历史帧、时间戳和 prefix 也可能不同。固定随机流、历史和输入后仍有差异，再检查数值非确定性和后端。

**为什么扩大动作块不一定更稳定？**
块内更连贯、推理次数更少，但遇到新障碍和物体变化时反应慢，错误轨迹可能执行更久。

**为什么缩短动作块也不一定更安全？**
频繁重规划会产生更多接缝、推理负载和队列抖动，模型误差也更频繁地打断运动。

**为什么预测轨迹发散时要缩短 horizon？**
轨迹分歧大说明动作模式可能正在变化，提前重新观测比长期执行旧预测更可靠；但阈值需避免正常快速动作被误切。

**为什么单连接服务不能同时跑多个推理？**
请求和响应没有天然配对时，多个推理可能交错读写同一条连接，导致结果错配。需要一个请求在途标志、请求编号和明确的取消协议。

**为什么“线程已结束”不等于“结果可用”？**
线程可能异常退出、超时或返回非法动作。结果还需检查状态、形状、有限值和请求代次。

**为什么超时后不能无限重启推理线程？**
旧线程仍可能持有连接和资源，迟到响应还会污染新会话。应取消旧代次、检查基础设施和限制重试。

**为什么推理线程看门狗不能替代控制循环超时？**
推理只是上游；主控制循环仍可能因锁、发布或线程调度卡住，两层都需要独立时限。

**为什么动作缓存必须记录产生时间和任务代次？**
格式相同的数组可能来自旧观测或另一个任务，不能只按形状判断可执行。

**为什么用一个随机 seed 仍可能无法复现 GPU 结果？**
多卡随机流、归约顺序、算子、采样进度和编译后端都可能改变结果。

#### 命令与安全

**为什么命令变化门限不是速度限制？**
它只检查相邻控制命令跳变，不能表达持续速度、加速度、接触力、碰撞和机械急停。

**为什么把门限调大可能让机器人更危险？**
真实危险跳变也会被放过；更正确的做法是区分模型采样、块接缝、控制增益和机械反馈来源。

**为什么暂停后必须重新观测？**
暂停期间环境、机器人姿态和人工接管都可能改变，旧缓存和旧 prefix 不再代表当前条件。

**为什么人工释放不能自动恢复模型？**
操作员松手不等于安全条件恢复，应由明确的状态检查与人工确认触发。

**为什么发现多个命令发布者时要告警？**
同一机器人可能同时被 Web 网关、遥操作和策略控制，命令会互相覆盖，导致抖动或不可预测运动。

**为什么“关节没有命令”不等于“机器人已经停”？**
控制器可能仍在跟踪最后目标，机械也可能因惯性和接触继续运动；要检查实际关节反馈和速度。

#### 数据与训练

**为什么少量黑帧不能静默当正常样本？**
模型可能把黑屏与特定动作建立伪相关；应标记来源，屏蔽不可靠监督或触发重采。

**为什么无效维度要用 mask，而不是全补零？**
补零会被损失解释为“目标动作就是零”，产生错误监督。

**为什么只对最终 loss 乘 mask 还不够？**
噪声、前缀、辅助目标和时间监督也必须使用一致的有效范围，否则无效数据仍会影响生成路径。

**为什么数据变大后平均 loss 与旧实验不可直接比较？**
任务比例、样本难度和辅助目标权重都变化了，需要按任务分层和统一评测。

**为什么多个任务一起训练也可能更差？**
数据规模不均、本体动作语义冲突和共享容量有限会造成负迁移。

**为什么数据去重不等于去掉相邻帧？**
机器人轨迹本质上相邻、连续，去重目标应是重复来源和评测泄漏，而不是破坏动作时间结构。

#### 部署与资源

**为什么推理服务的端口能连接却可能连错任务？**
端口可以被旧进程或其他版本占用，必须结合进程归属、metadata 和模型资产确认服务身份。

**为什么重启服务会改变首次请求延迟？**
编译缓存、显存分配、算子选择和图像缓存可能重新初始化。

**为什么要给 warmup 输出保存固定输入指纹？**
可以比较新版本、不同后端和不同设备是否发生静默数值变化。

**为什么多个模型单独加载都能成功却同时 OOM？**
常驻权重之外还有 CUDA context、临时激活、编译缓存和并发请求峰值。

**为什么杀进程后还要检查动作发布者？**
其他节点或子进程仍可能发布控制命令，锁释放不等于物理控制已经空闲。

**为什么健康检查只返回 HTTP 200 不够？**
应检查模型、norm、相机、动作契约、控制器和实际发布链。

#### 真实面试中的评分方式

回答工程现象题时，面试官通常观察四种能力：

1. **是否能定义现象**：不把“抖”与“慢”“迟滞”“漂移”“振荡”混为一谈。
2. **是否能建立时间线**：知道观测、请求、推理、队列、发布和反馈各发生在什么时刻。
3. **是否能设计可证伪检查**：提出消融、固定输入、离线回放和命令/反馈对照。
4. **是否有安全边界**：知道何时应停止、清状态和重新武装，而不是只调参数。

#### 六步答题法

- **现象**：持续抖动、接缝回跳、整体滞后、偶发超时还是任务假完成。
- **时间线**：输入何时采集，请求何时发出，模型何时返回，动作何时执行。
- **契约**：相机、状态、动作、单位、norm、horizon、prefix 是否同代。
- **资源**：CPU、GPU、显存、网络、队列、锁和并发是否充足。
- **控制与物理**：命令和实际关节反馈是否一致，是否存在接触与机械问题。
- **安全与验证**：先停止还是降级，如何清除状态、恢复，并用回放和分层测试证明修复。


### 面试官最常继续追问的 20 个工程判断

这一节专门把“工程实现里有，但四册正文只讲原理”的问题提升为面试考点。面试官通常不会问内部文件名，而会继续追问为什么、失效条件、如何证明和怎样恢复。

#### 1. 为什么片上滤波参数要和发布频率一起看

同样的截止频率，如果实际发布频率变了，滤波的相对影响和相位延迟都会改变。还要检查算法使用的采样频率是否等于真实控制频率。

**追问**：如果控制循环偶尔变慢，离线按固定频率设计的滤波是否仍成立？

**回答**：不完全成立。应记录真实时间间隔，必要时用带时间语义的滤波或先稳定控制周期，否则滤波和动作速度都会偏移。

#### 2. 为什么滑动平均不能替代所有低通

滑动平均实现简单，但窗口和阶数固定时可能带来较大延迟；低通可设计截止频率，连续时间语义更明确。选择要看噪声频率、任务带宽和控制周期。

#### 3. 为什么采样频率低于控制频率时不能简单重复最后一个动作

重复最后命令相当于零阶保持，短时可用于维持，但长时间会积累过期控制；在速度、接触或运动目标上可能产生停顿与跳变。必须有动作年龄和队列耗尽策略。

#### 4. 为什么动作块对齐不能只依据推理耗时

推理耗时只告诉过去了多久，不知道机器人实际执行到哪里、减速快慢、控制器是否丢拍。实际关节状态、已执行索引和消费时间更可靠。

#### 5. 为什么实际操作频率会影响归一化和单位

如果训练动作记录频率和部署发布频率不同，同一个动作增量在单位时间内产生的物理速度不同。训练、数据 fps 和控制频率必须一起核对。

#### 6. 为什么模型动作平滑但机器人仍可能加速过大

位置目标平滑不代表二阶导数平滑。高频小步长、控制器跟踪误差和相位延迟都可能产生较大速度与加速度。

**追问**：仅检查最大位置差是否足够？

**回答**：不够，还要检查速度、加速度和接触冲击。

#### 7. 为什么普通动作限幅可能改变任务语义

对绝对关节或末端目标局部裁剪，会让真实位置偏离期望；对一些依赖相对位置和接触的夹取，偏差会改变后续动作。

#### 8. 为什么异常清洗和滤波要分开

异常清洗是发现错误测量、坏帧和非有限值；滤波是抑制正常高频噪声。用量化、裁剪或平滑隐藏异常会把检查问题变成训练偏差。

#### 9. 为什么状态估计的滤波延迟会影响 VLA

模型看到的是过去时刻的自身状态；控制命令又作用于当前状态。融合延迟和动作延迟叠加，可能造成过补偿或振荡。

#### 10. 为什么多帧图像缓存和状态历史要分开管理

相机帧、关节状态、动作和事件频率不同。简单按同一索引对齐会错位。应按时间戳或指定同步间隔联合生成样本。

#### 11. 为什么缓存命中率提升，端到端控制却可能更慢

缓存命中不等于关键路径更短。可能是预取线程占用了 CPU，或缓存了过期大图，增加内存、锁和传输成本。

#### 12. 为什么随机增强和随机推理采样要分开

训练增强有意制造数据变化；推理采样应表达策略不确定性。把两者都称为随机性会导致无法定位抖动来源。

#### 13. 为什么 data shuffle 的变化会影响训练可复现和评测

采样顺序影响有效任务比例和 batch 组成。跨 epoch 恢复时，如果只保存模型权重而没有采样索引，训练轨迹与断点恢复不一致。

#### 14. 为什么分布式训练的数据副本不一定是好事

如果多个模型副本共享同一 batch，或重复数据没有被正确合并，会增加重复样本、通信和不一致梯度。必须理解副本是并行数据还是同步模型副本。

#### 15. 为什么校验点保存频率会影响 GPU 利用率

大模型 checkpoint 需要聚合参数和写盘。保存期间计算、通信和存储可能互相阻塞，长任务会出现周期性的 step 尖峰。

#### 16. 为什么指标平均值正常仍可能有严重尾部故障

控制任务关心最坏情况。少量超过预算的请求就能耗尽动作缓存，造成机器人停顿或安全触发。应报告 p95、p99、最大值和超时率。

#### 17. 为什么故障恢复要验证“重新开始后仍一致”

恢复不只是进程能重新运行，还要确认模型、相机、配置和控制器没有混用，动作输出与上一版本一致，队列与历史清空。

#### 18. 为什么服务器主动压缩网络帧可能反而增加延迟

压缩减少传输字节，但编码和解码占用 CPU，且引入排队时间。只有传输确实成为瓶颈时，整体才可能收益。

#### 19. 为什么优化某个相机的传输会改变模型输入语义

每台相机的重要性、分辨率和压缩质量可能不同。把主视角降得过低会丢失任务关键细节，而腕部相机降得过重会影响接触。

#### 20. 为什么“没有错误日志”不能作为验收依据

库和框架可能静默回退、忽略字段或跳过无效样本。验收必须检查实际输入、输出、控制发布和闭环结果。

### 面试现场的表述顺序

回答一个工程题时，最后应明确说明：

- 先做什么检查，能快速排除哪一层。
- 哪些现象仍存在时，说明根因更深。
- 修复方法是数据、时序、资源还是控制。
- 修复后用什么指标证明有效。
- 在什么安全条件下允许恢复。

这比直接报一个参数值和“加一个滤波”更容易获得追问后的高分。

### 一页总结

工程面试里的高频问题有一半不是新算法，而是同一个系统的不同故障表现。消抖要跨越数据、模型、调度、控制和机械；推理超时要跨越观测、队列、TTC 与安全；部署失败要跨越端口、进程、资产、协议和控制器。

回答这类题的核心公式是：**先定位时间和状态，再检查契约与所有权，然后观察资源和并发，最后才调模型与滤波参数。**

### 6. 面经问题的证据等级

| 证据等级 | 含义 | 用法 |
|---|---|---|
| 公开多名作者重复出现 | 题目主题较稳定 | 作为高频主线 |
| 单篇公开面经 | 某岗位真实出现过 | 保留背景，不泛化为全行业 |
| 官方文档或论文 | 技术定义和机制可靠 | 校准答案与术语 |
| 本库项目实践 | 在特定机器人上验证过 | 只说明该条件下的工程经验 |
| 实验或传闻 | 缺少公开复现 | 标为待验证，不作为确定答案 |

**本库不声称统计了无法公开核验的原始面试次数。** 对 CSDN、知乎和不同 GitHub 题库的频次标签，应理解为参考信号，而不是统一行业调查。

### 7. 已验证与未验证边界

#### 已有较强工程证据的方法

- 相机、动作和状态接口不一致会导致“服务正常但行为错误”。
- 动作队列和推理延迟必须有时效管理。
- TTC 需要覆盖真实执行前缀，延迟超过训练范围会退化。
- 多帧输入应按时间而非推理次数组织。
- ROS/导航问题需要同时检查 TF、定位、地图、代价、控制和恢复。
- 多模态动作输入、模型预热、独占控制和显式协议对系统可靠性有直接价值。

#### 仍需持续验证的结论

- FAST token 辅助目标能否稳定提升真机成功率，依赖任务和数据。
- Diffusion 与 Flow 在不同控制频率、接触和动作维度上的优劣不统一。
- 跨本体共享在什么数据规模下从负迁移变成正迁移。
- 世界模型在接触丰富真实任务中的长时预测稳定性。
- 视觉语言导航从仿真到真实走廊、人群和新物体时的鲁棒性。
- 多帧历史和连续重规划的独立贡献与最优时间尺度。
- 量化、FP8、编译和低步数生成对不同机器人动作安全边界的影响。

### 9. 新增题目的写法

新增一条主题时使用：

- **问题**：读者或面试官在问什么。
- **基础做法**：最直观的版本。
- **改进**：增加的信息、目标或约束。
- **为什么可能有效**：解释机制而不是重复定义。
- **代价与风险**：说明延迟、显存、数据、误差和安全边界。
- **适用场景**：何时值得使用。
- **面试怎么答**：一段可以口头复述的完整答案。
- **验证证据**：分别标明论文、仿真、真机或单次经验。

#### 不应加入的内容

- 只对某内部项目可理解的文件名和函数名。
- 未经脱敏的账号、密钥、生产路径和公司内部数据。
- 把单次成功写成通用规律。
- 纯粹复制外部题库而不核对。
- 同一概念换几个近义词重复建条目。
- 只有结论、没有机制和失败边界的“口诀”。
